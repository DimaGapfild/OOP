# Chapter 7. Abstraction and Interfaces

## 7.1 What Is Abstraction

**Abstraction** means picking out what is essential and hiding the details. The user
of a class knows **what** it does, but not **how**. Abstraction answers the
question "what is the contract?", while encapsulation (chapter 3) answers "how do we
protect this contract?".

An **abstract class** is a class that describes the common basis of its children but
is not itself meant for creating objects: it leaves some methods
**abstract** (without an implementation) and obliges its children to implement them.

## 7.2 Abstract Classes

**Python**

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...

    @abstractmethod
    def perimeter(self) -> float: ...

    def describe(self) -> str:                 # a regular method — the implementation is shared
        return f"{type(self).__name__}: S={self.area():.2f}"


class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2
    def perimeter(self): return 4 * self.a


Shape()          # TypeError: Can't instantiate abstract class
Square(2)        # works, because ALL abstract methods are implemented
```

**JavaScript** — there are no abstract classes; they are imitated by
checking `new.target` in the constructor:

```js
class Shape {
    constructor() {
        if (new.target === Shape) {
            throw new TypeError("Shape is an abstract class");
        }
    }

    area()      { throw new Error("area() is not implemented"); }
    perimeter() { throw new Error("perimeter() is not implemented"); }

    describe() {                               // a regular method — the implementation is shared
        return `${this.constructor.name}: S=${this.area().toFixed(2)}`;
    }
}

class Square extends Shape {
    constructor(a) { super(); this.a = a; }
    area()      { return this.a ** 2; }
    perimeter() { return 4 * this.a; }
}

new Shape();     // TypeError
new Square(2);   // works
```

**C++** — a **pure virtual** method (`= 0`) makes the class abstract:

```cpp
#include <format>
#include <string>
#include <typeinfo>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual double perimeter() const = 0;

    std::string describe() const {             // a regular method — the implementation is shared
        return std::format("S={:.2f}", area());
    }
};

class Square : public Shape {
public:
    explicit Square(double a) : a(a) {}
    double area() const override      { return a * a; }
    double perimeter() const override { return 4 * a; }
private:
    double a;
};

// Shape s;      // compile error: abstract class
Square sq(2);    // works, because ALL pure virtual methods are implemented
```

If a child has not implemented **all** abstract methods, it is abstract
too, and an object of it cannot be created.

Abstract properties:

**Python**

```python
class Vehicle(ABC):
    @property
    @abstractmethod
    def max_speed(self) -> float: ...
```

**JavaScript**

```js
class Vehicle {
    get maxSpeed() { throw new Error("maxSpeed is not implemented"); }
}
```

**C++** — there are no properties, so it is a regular pure virtual method:

```cpp
class Vehicle {
public:
    virtual ~Vehicle() = default;
    virtual double maxSpeed() const = 0;
};
```

> **Language difference: when an unimplemented abstract method is noticed.**
>
> | Python | JavaScript | C++ |
> |---|---|---|
> | `TypeError` when the object is **created** | no error until the unimplemented method is **called** (and only if the base method throws) | a **compile** error when trying to create the object |
>
> In JS a forgotten method can "live" in the program unnoticed for a long time.

## 7.3 The Template Method

An abstract class defines the **skeleton of an algorithm** and leaves the steps to its children:

**Python**

```python
class Report(ABC):
    def build(self) -> str:                    # the skeleton — not overridden
        return "\n".join([self.header(), *self.body(), self.footer()])

    @abstractmethod
    def header(self) -> str: ...
    @abstractmethod
    def body(self) -> list[str]: ...
    def footer(self) -> str:                   # a "hook" with a default value
        return "-- end --"
```

**JavaScript**

```js
class Report {
    build() {                                  // the skeleton
        return [this.header(), ...this.body(), this.footer()].join("\n");
    }

    header() { throw new Error("not implemented"); }
    body()   { throw new Error("not implemented"); }
    footer() { return "-- end --"; }           // a "hook" with a default value
}
```

**C++** — the skeleton is non-virtual so subclasses cannot change it:

```cpp
#include <string>
#include <vector>

class Report {
public:
    virtual ~Report() = default;

    std::string build() const {                // the skeleton — not virtual
        std::string out = header() + "\n";
        for (const auto& line : body()) out += line + "\n";
        return out + footer();
    }

protected:
    virtual std::string header() const = 0;
    virtual std::vector<std::string> body() const = 0;
    virtual std::string footer() const {       // a "hook" with a default value
        return "-- end --";
    }
};
```

## 7.4 Interface

An **interface** is a set of methods that a class promises to implement, with no
implementation at all. In Python:

| Approach | Checked | When |
|----------|---------|------|
| abstract class (`ABC`) | when an object is created | when there is shared code |
| `typing.Protocol` | statically (mypy) / `isinstance` with `@runtime_checkable` | "structural" typing, without inheritance |
| `collections.abc` (`Sequence`, `Mapping`, `Iterable`…) | ready-made standard-library interfaces | implement the minimum — get the rest for free |

**Python**

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Drawable(Protocol):
    def draw(self) -> str: ...

isinstance(Circle(), Drawable)     # True if a draw method exists (no inheritance needed)
```

**JavaScript** — there are no formal interfaces; the presence of a
method is checked:

```js
const isDrawable = (obj) => typeof obj?.draw === "function";

isDrawable(new Circle());          // true if a draw method exists
```

**C++** — an interface is a class with only pure virtual methods; a
structural check (like `Protocol`) is provided by a C++20 concept:

```cpp
class Drawable {                   // a nominal interface
public:
    virtual ~Drawable() = default;
    virtual std::string draw() const = 0;
};

template <typename T>              // a structural "protocol"
concept DrawableLike = requires(const T& t) { t.draw(); };

static_assert(DrawableLike<Circle>);   // true if a draw method exists
```

A class can implement **several** interfaces (`class File(Readable, Writable)`).

## 7.5 Program to an Interface, Not an Implementation

**Python**

```python
class OrderService:
    def __init__(self, logger: Logger):        # we depend on an ABSTRACTION
        self.logger = logger
```

**JavaScript**

```js
class OrderService {
    constructor(logger) {              // any object with a log() method
        this.logger = logger;
    }
}
```

**C++**

```cpp
class Logger {
public:
    virtual ~Logger() = default;
    virtual void log(const std::string& msg) = 0;
};

class OrderService {
public:
    explicit OrderService(Logger& logger)      // we depend on an ABSTRACTION
        : logger(logger) {}

private:
    Logger& logger;
};
```

Now you can pass a `ConsoleLogger`, in a test a `ListLogger`, in production a
`FileLogger`; `OrderService` does not change. This is **dependency inversion**
(chapter 11, principle D).

## 7.6 Comparison with Other Languages

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Abstract class | `ABC` + `@abstractmethod` | none; `new.target` + `throw` | a class with a **pure virtual** method `= 0` |
| Interface | `ABC`/`Protocol` | duck typing | a class with pure virtual methods only |
| Error | `TypeError` on creation | on call/creation (manually) | a **compile error** |
| Destructor | — | — | `virtual ~I() = default;` is mandatory |
