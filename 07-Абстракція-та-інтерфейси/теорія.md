# Розділ 7. Абстракція та інтерфейси

## 7.1 Що таке абстракція

**Абстракція** — виділення істотного й приховування деталей. Користувач
класу знає, **що** той робить, але не **як**. Абстракція відповідає на
питання «який контракт?», інкапсуляція (розділ 3) — «як цей контракт
захистити?».

**Абстрактний клас** — клас, що описує спільну основу нащадків, але
сам не призначений для створення об'єктів: частину методів він лишає
**абстрактними** (без реалізації) і зобов'язує нащадків їх реалізувати.

## 7.2 Абстрактні класи

**Python**

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...

    @abstractmethod
    def perimeter(self) -> float: ...

    def describe(self) -> str:                 # звичайний метод — реалізація спільна
        return f"{type(self).__name__}: S={self.area():.2f}"


class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2
    def perimeter(self): return 4 * self.a


Shape()          # TypeError: Can't instantiate abstract class
Square(2)        # працює, бо реалізовано ВСІ абстрактні методи
```

**JavaScript** — абстрактних класів немає; їх імітують перевіркою
`new.target` у конструкторі:

```js
class Shape {
    constructor() {
        if (new.target === Shape) {
            throw new TypeError("Shape — абстрактний клас");
        }
    }

    area()      { throw new Error("area() не реалізовано"); }
    perimeter() { throw new Error("perimeter() не реалізовано"); }

    describe() {                               // звичайний метод — реалізація спільна
        return `${this.constructor.name}: S=${this.area().toFixed(2)}`;
    }
}

class Square extends Shape {
    constructor(a) { super(); this.a = a; }
    area()      { return this.a ** 2; }
    perimeter() { return 4 * this.a; }
}

new Shape();     // TypeError
new Square(2);   // працює
```

**C++** — **чисто віртуальний** метод (`= 0`) робить клас абстрактним:

```cpp
#include <format>
#include <string>
#include <typeinfo>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual double perimeter() const = 0;

    std::string describe() const {             // звичайний метод — реалізація спільна
        return std::format("S={:.2f}", area());
    }
};

class Square : public Shape {
public:
    explicit Square(double a) : a(a) {}
    double area() const override      { return a * a; }
    double perimeter() const override { return 4 * a; }
private:
    double a;
};

// Shape s;      // помилка компіляції: абстрактний клас
Square sq(2);    // працює, бо реалізовано ВСІ чисто віртуальні методи
```

Якщо нащадок не реалізував **усіх** абстрактних методів — він теж
абстрактний, і створити його об'єкт неможливо.

Абстрактні властивості:

**Python**

```python
class Vehicle(ABC):
    @property
    @abstractmethod
    def max_speed(self) -> float: ...
```

**JavaScript**

```js
class Vehicle {
    get maxSpeed() { throw new Error("maxSpeed не реалізовано"); }
}
```

**C++** — властивостей немає, тож це звичайний чисто віртуальний метод:

```cpp
class Vehicle {
public:
    virtual ~Vehicle() = default;
    virtual double maxSpeed() const = 0;
};
```

> **Різниця між мовами: коли помітно, що абстрактний метод не реалізовано.**
>
> | Python | JavaScript | C++ |
> |---|---|---|
> | `TypeError` під час **створення** об'єкта | помилки немає, доки не **викличуть** нереалізований метод (і то лише якщо базовий метод кидає виняток) | помилка **компіляції** при спробі створити об'єкт |
>
> У JS забутий метод може «прожити» в програмі довго й непомітно.

## 7.3 Шаблонний метод (Template Method)

Абстрактний клас задає **скелет алгоритму**, а кроки віддає нащадкам:

**Python**

```python
class Report(ABC):
    def build(self) -> str:                    # скелет — не перевизначається
        return "\n".join([self.header(), *self.body(), self.footer()])

    @abstractmethod
    def header(self) -> str: ...
    @abstractmethod
    def body(self) -> list[str]: ...
    def footer(self) -> str:                   # «гачок» зі значенням за замовчуванням
        return "-- кінець --"
```

**JavaScript**

```js
class Report {
    build() {                                  // скелет
        return [this.header(), ...this.body(), this.footer()].join("\n");
    }

    header() { throw new Error("не реалізовано"); }
    body()   { throw new Error("не реалізовано"); }
    footer() { return "-- кінець --"; }        // «гачок» зі значенням за замовчуванням
}
```

**C++** — скелет робимо невіртуальним, щоб нащадки не могли його змінити:

```cpp
#include <string>
#include <vector>

class Report {
public:
    virtual ~Report() = default;

    std::string build() const {                // скелет — не virtual
        std::string out = header() + "\n";
        for (const auto& line : body()) out += line + "\n";
        return out + footer();
    }

protected:
    virtual std::string header() const = 0;
    virtual std::vector<std::string> body() const = 0;
    virtual std::string footer() const {       // «гачок» зі значенням за замовчуванням
        return "-- кінець --";
    }
};
```

## 7.4 Інтерфейс

**Інтерфейс** — набір методів, який зобов'язується реалізувати клас, без
жодної реалізації. У Python:

| Спосіб | Перевірка | Коли |
|--------|-----------|------|
| абстрактний клас (`ABC`) | під час створення об'єкта | коли є спільний код |
| `typing.Protocol` | статична (mypy) / `isinstance` з `@runtime_checkable` | «структурна» типізація, без успадкування |
| `collections.abc` (`Sequence`, `Mapping`, `Iterable`…) | готові інтерфейси стандартної бібліотеки | реалізуйте мінімум — отримайте решту безкоштовно |

**Python**

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Drawable(Protocol):
    def draw(self) -> str: ...

isinstance(Circle(), Drawable)     # True, якщо є метод draw (успадкування не потрібне)
```

**JavaScript** — формальних інтерфейсів немає; перевіряють наявність
методу:

```js
const isDrawable = (obj) => typeof obj?.draw === "function";

isDrawable(new Circle());          // true, якщо є метод draw
```

**C++** — інтерфейс = клас лише з чисто віртуальними методами;
структурну перевірку (як `Protocol`) дає концепт C++20:

```cpp
class Drawable {                   // номінальний інтерфейс
public:
    virtual ~Drawable() = default;
    virtual std::string draw() const = 0;
};

template <typename T>              // структурний «протокол»
concept DrawableLike = requires(const T& t) { t.draw(); };

static_assert(DrawableLike<Circle>);   // true, якщо є метод draw
```

Клас може реалізовувати **кілька** інтерфейсів (`class File(Readable, Writable)`).

## 7.5 Програмуйте до інтерфейсу, а не до реалізації

**Python**

```python
class OrderService:
    def __init__(self, logger: Logger):        # залежимо від АБСТРАКЦІЇ
        self.logger = logger
```

**JavaScript**

```js
class OrderService {
    constructor(logger) {              // будь-який об'єкт із методом log()
        this.logger = logger;
    }
}
```

**C++**

```cpp
class Logger {
public:
    virtual ~Logger() = default;
    virtual void log(const std::string& msg) = 0;
};

class OrderService {
public:
    explicit OrderService(Logger& logger)      // залежимо від АБСТРАКЦІЇ
        : logger(logger) {}

private:
    Logger& logger;
};
```

Зараз можна передати `ConsoleLogger`, у тесті — `ListLogger`, у проді —
`FileLogger`; `OrderService` не змінюється. Це **інверсія залежностей**
(розділ 11, принцип D).

## 7.6 Порівняння з іншими мовами

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Абстрактний клас | `ABC` + `@abstractmethod` | немає; `new.target` + `throw` | клас із **чисто віртуальним** методом `= 0` |
| Інтерфейс | `ABC`/`Protocol` | duck typing | клас лише з чисто віртуальними методами |
| Помилка | `TypeError` під час створення | під час виклику/створення (вручну) | **помилка компіляції** |
| Деструктор | — | — | `virtual ~I() = default;` обов'язково |
