# Chapter 2. Constructors, Attributes, Methods

## 2.1 The Constructor

The constructor is called automatically when an object is created and
sets its initial state.

**Python**

```python
class Employee:
    def __init__(self, name: str, salary: float = 10000):
        self.name = name
        self.salary = salary

e1 = Employee("Koval")             # salary = 10000
e2 = Employee("Bondar", salary=25000)
```

**JavaScript**

```js
class Employee {
    constructor(name, salary = 10000) {
        this.name = name;
        this.salary = salary;
    }
}

const e1 = new Employee("Koval");           // salary = 10000
const e2 = new Employee("Bondar", 25000);
```

**C++**

```cpp
class Employee {
public:
    std::string name;
    double salary;

    Employee(std::string name, double salary = 10000)
        : name(name), salary(salary) {}
};

Employee e1("Koval");                        // salary = 10000
Employee e2("Bondar", 25000);
```

Good practices:

- create all fields **in the constructor** (so the object's full "makeup" is visible);
- give every field an **initial value** right away;
- a mutable default (list, array) **must not be shared** by all objects —
  each one gets its own copy.

The last rule is trickiest in Python: a default value is evaluated
**once**, when the function is defined:

**Python**

```python
def __init__(self, items=[]):       # BUG: one list shared by all objects
    self.items = items

def __init__(self, items=None):     # correct
    self.items = [] if items is None else list(items)
```

In JavaScript a default value is evaluated **on every call**, so the
trap does not exist; in C++ the parameter is passed by value (or by
const reference):

**JavaScript**

```js
constructor(items = []) {           // a new array on every call — safe
    this.items = [...items];        // a copy, so the array is not shared with the caller
}
```

**C++**

```cpp
explicit Cart(std::vector<std::string> items = {})
    : items(std::move(items)) {}    // each object owns its own copy
```

> **Language difference: named arguments.** Python allows
> `Employee("Bondar", salary=25000)`. JavaScript and C++ have no named
> arguments: `new Employee("Bondar", 25000)`. In JS, when there are many
> optional parameters, an object is passed:
>
> ```js
> constructor(name, { salary = 10000, position = "intern" } = {}) { ... }
> new Employee("Bondar", { salary: 25000 });
> ```

> **Language difference: uninitialized fields.** If the constructor
> "forgot" to set a field:
>
> | Python | JavaScript | C++ |
> |---|---|---|
> | the attribute does not exist — `AttributeError` on access | the value is `undefined` | an `int` field holds **random garbage** from memory (undefined behavior) |
>
> So in C++ always give initial values: `int pages = 0;` or via the
> initializer list.

## 2.2 Instance and Class Attributes

**Python**

```python
class Employee:
    company = "Soft LLC"            # a CLASS attribute — shared
    count = 0

    def __init__(self, name):
        self.name = name            # an INSTANCE attribute — its own
        Employee.count += 1
```

**JavaScript**

```js
class Employee {
    static company = "Soft LLC";    // a static field — shared
    static count = 0;

    constructor(name) {
        this.name = name;           // an instance field — its own
        Employee.count += 1;
    }
}
```

**C++**

```cpp
class Employee {
public:
    inline static std::string company = "Soft LLC";  // shared
    inline static int count = 0;

    std::string name;               // an instance field — its own

    explicit Employee(std::string name) : name(name) {
        ++count;
    }
};
```

| | Class attribute | Instance attribute |
|---|---|---|
| How many copies | one per class | one per object |
| Python | in the class body; `Employee.count` or `e.count` | in `__init__` via `self`; `e.name` |
| JavaScript | `static` in the class body; only `Employee.count` | in `constructor` via `this`; `e.name` |
| C++ | `static` in the class body; `Employee::count` or `e.count` | a field in the class body; `e.name` |

**A trap: reading and writing through an instance work differently.**

When you **read** `e1.company`, Python first looks for the attribute in
the object itself and, if it isn't there, in the class. So `e1.company`
returns the class's shared value.

When you **assign** `e1.company = ...`, Python does not look in the class:
the write always goes into the object itself. `e1` gets its own
`company` attribute, which "shadows" (hides) the class attribute — but
only for `e1`:

**Python**

```python
e1 = Employee("Koval")
e2 = Employee("Bondar")
print(e1.company, e2.company)     # Soft LLC Soft LLC — both read from the class

e1.company = "Other"              # the class is NOT changed: e1 gets its own attribute

print(e1.company)                 # Other    — e1's own attribute
print(e2.company)                 # Soft LLC — e2 still reads from the class
print(Employee.company)           # Soft LLC — the class is unchanged
```

To change the shared value for everyone, assign through the class:
`Employee.company = "Other"`. That is why the constructor above
increments the counter as `Employee.count += 1`: `self.count += 1` would
read the value from the class but write the result into the object's own
attribute, and the shared counter would stay at `0`.

In JavaScript a static field is not visible through an instance at all
(`e1.company` is `undefined`), so the assignment simply adds a new,
ordinary field to `e1` that has nothing to do with the static one. In
C++ it is the opposite: `e1.company` is just another way to write
`Employee::company`, so the assignment changes the shared field **for
every** object:

**JavaScript**

```js
console.log(e1.company);          // undefined — a static field is visible only through the class
e1.company = "Other";             // a new field only in e1
console.log(Employee.company);    // Soft LLC — unchanged
```

**C++**

```cpp
e1.company = "Other";             // changes the SHARED static field!
std::cout << Employee::company;   // Other
```

## 2.3 Instance, Class, and Static Methods

**Python**

```python
class Temperature:
    def __init__(self, celsius: float):
        self.celsius = celsius

    def to_fahrenheit(self) -> float:          # instance method (self)
        return self.celsius * 9 / 5 + 32

    @classmethod
    def from_fahrenheit(cls, f: float):        # class method (cls)
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_valid(celsius: float) -> bool:      # static (no self/cls)
        return celsius >= -273.15


t = Temperature.from_fahrenheit(212)           # 100.0 °C
```

**JavaScript**

```js
class Temperature {
    constructor(celsius) {
        this.celsius = celsius;
    }

    toFahrenheit() {                           // instance method (this)
        return this.celsius * 9 / 5 + 32;
    }

    static fromFahrenheit(f) {                 // static; this is the class itself
        return new this((f - 32) * 5 / 9);
    }

    static isValid(celsius) {
        return celsius >= -273.15;
    }
}

const t = Temperature.fromFahrenheit(212);     // 100 °C
```

**C++** — there is no separate "class method", only `static`:

```cpp
class Temperature {
public:
    explicit Temperature(double celsius) : celsius(celsius) {}

    double toFahrenheit() const {              // instance method (this)
        return celsius * 9 / 5 + 32;
    }

    static Temperature fromFahrenheit(double f) {   // static
        return Temperature((f - 32) * 5 / 9);
    }

    static bool isValid(double celsius) {
        return celsius >= -273.15;
    }

    double celsius;
};

Temperature t = Temperature::fromFahrenheit(212);   // 100 °C
```

| Kind | First parameter | Has access to | Typical purpose |
|------|----------------|---------------|-----------------|
| regular | `self` | the object and the class | working with the object's data |
| `@classmethod` | `cls` | the class | alternative constructors |
| `@staticmethod` | none | nothing | helper functions that logically "live" in the class |

> **Language difference: calling a static method.**
>
> ```python
> t.is_valid(5)            # works: a static method is reachable through an object too
> ```
>
> ```js
> t.isValid(5);            // TypeError: t.isValid is not a function
> Temperature.isValid(5);  // correct — only through the class
> ```
>
> ```cpp
> t.isValid(5);            // works, but Temperature::isValid(5) is the convention
> ```
>
> One more JS trap: a class cannot be called without `new` —
> `Temperature(100)` throws `TypeError: Class constructor Temperature
> cannot be invoked without 'new'`. Python does not need `new` at all,
> and in C++ `new` means something else — allocation on the heap (see
> chapter 8).

## 2.4 Alternative Constructors

Python has no constructor overloading. Instead, use
`@classmethod` "factories":

**Python**

```python
class Date:
    def __init__(self, y, m, d):
        self.y, self.m, self.d = y, m, d

    @classmethod
    def from_string(cls, s: str):              # "2026-10-05"
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)
```

**JavaScript** — also has only one constructor, so static factories
are used:

```js
class DateValue {
    constructor(y, m, d) {
        [this.y, this.m, this.d] = [y, m, d];
    }

    static fromString(s) {                     // "2026-10-05"
        const [y, m, d] = s.split("-").map(Number);
        return new this(y, m, d);
    }
}
```

**C++** — constructors can be **overloaded**:

```cpp
#include <sstream>

class Date {
public:
    Date(int y, int m, int d) : y(y), m(m), d(d) {}

    explicit Date(const std::string& s) {      // "2026-10-05"
        char dash;
        std::istringstream in(s);
        in >> y >> dash >> m >> dash >> d;
    }

private:
    int y, m, d;
};
```

Using `cls` (rather than hard-coding `Date`) lets subclasses use the factory too.

## 2.5 Method Chaining (Fluent Interface)

If a method returns `self`, calls can be chained:

**Python**

```python
class Pizza:
    def __init__(self):
        self.toppings = []

    def add(self, t):
        self.toppings.append(t)
        return self                    # <- the key part

p = Pizza().add("cheese").add("mushrooms").add("ham")
```

**JavaScript**

```js
class Pizza {
    constructor() {
        this.toppings = [];
    }

    add(t) {
        this.toppings.push(t);
        return this;                   // <- the key part
    }
}

const p = new Pizza().add("cheese").add("mushrooms").add("ham");
```

**C++** — return a **reference** to `*this`, otherwise every call
would operate on a copy:

```cpp
class Pizza {
public:
    Pizza& add(const std::string& t) {
        toppings.push_back(t);
        return *this;                  // <- the key part
    }

private:
    std::vector<std::string> toppings;
};

Pizza p;
p.add("cheese").add("mushrooms").add("ham");
```

> **C++ trap: the "most vexing parse".** Empty parentheses in a variable
> declaration turn it into a **function** declaration:
>
> ```cpp
> Pizza p();               // this declares a function p that returns Pizza!
> p.add("cheese");         // compile error
> Pizza q;                 // correct
> Pizza r{};               // also correct
> ```
>
> Python and JavaScript do not have this problem: `Pizza()` /
> `new Pizza()` always create an object.

## 2.6 Comparison with Other Languages

| Task | Python | JavaScript | C++ |
|------|--------|-----------|-----|
| Default value | `def f(x=0)` | `constructor(x = 0)` | `A(int x = 0)` |
| Class attribute | in the class body | `static count = 0;` | `static int count;` (+ a definition outside the class, or `inline`) |
| Class method | `@classmethod` | `static create()` | `static A create()` |
| Several constructors | factories | factories | constructor **overloading** |
