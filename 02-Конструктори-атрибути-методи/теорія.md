# Розділ 2. Конструктори, атрибути, методи

## 2.1 Конструктор

Конструктор викликається автоматично під час створення об'єкта і
задає його початковий стан.

**Python**

```python
class Employee:
    def __init__(self, name: str, salary: float = 10000):
        self.name = name
        self.salary = salary

e1 = Employee("Коваль")             # salary = 10000
e2 = Employee("Бондар", salary=25000)
```

**JavaScript**

```js
class Employee {
    constructor(name, salary = 10000) {
        this.name = name;
        this.salary = salary;
    }
}

const e1 = new Employee("Коваль");          // salary = 10000
const e2 = new Employee("Бондар", 25000);
```

**C++**

```cpp
class Employee {
public:
    std::string name;
    double salary;

    Employee(std::string name, double salary = 10000)
        : name(name), salary(salary) {}
};

Employee e1("Коваль");                       // salary = 10000
Employee e2("Бондар", 25000);
```

Гарні практики:

- усі поля створювати **в конструкторі** (щоб бачити повний «склад» об'єкта);
- кожному полю одразу давати **початкове значення**;
- змінне значення за замовчуванням (список, масив) **не має бути спільним**
  для всіх об'єктів — кожен отримує власну копію.

Найпідступніше останнє правило в Python: значення за замовчуванням
обчислюється **один раз**, під час оголошення функції:

**Python**

```python
def __init__(self, items=[]):       # ПОМИЛКА: один список на всі об'єкти
    self.items = items

def __init__(self, items=None):     # правильно
    self.items = [] if items is None else list(items)
```

У JavaScript значення за замовчуванням обчислюється **при кожному
виклику**, тож пастки немає; у C++ параметр передається копією
(або константним посиланням):

**JavaScript**

```js
constructor(items = []) {           // новий масив на кожен виклик — безпечно
    this.items = [...items];        // копія, щоб не ділити масив із викликачем
}
```

**C++**

```cpp
explicit Cart(std::vector<std::string> items = {})
    : items(std::move(items)) {}    // власна копія для кожного об'єкта
```

> **Різниця між мовами: іменовані аргументи.** Python дозволяє
> `Employee("Бондар", salary=25000)`. У JavaScript і C++ іменованих
> аргументів немає: `new Employee("Бондар", 25000)`. У JS для багатьох
> необов'язкових параметрів передають об'єкт:
>
> ```js
> constructor(name, { salary = 10000, position = "стажер" } = {}) { ... }
> new Employee("Бондар", { salary: 25000 });
> ```

> **Різниця між мовами: неініціалізовані поля.** Якщо конструктор
> «забув» задати поле:
>
> | Python | JavaScript | C++ |
> |---|---|---|
> | атрибута немає — `AttributeError` під час звернення | значення `undefined` | поле `int` містить **випадкове «сміття»** з пам'яті (невизначена поведінка) |
>
> Тому в C++ завжди задавайте початкові значення: `int pages = 0;` або
> через список ініціалізації.

## 2.2 Атрибути екземпляра та класу

**Python**

```python
class Employee:
    company = "ТОВ «Софт»"          # атрибут КЛАСУ — спільний
    count = 0

    def __init__(self, name):
        self.name = name            # атрибут ЕКЗЕМПЛЯРА — власний
        Employee.count += 1
```

**JavaScript**

```js
class Employee {
    static company = "ТОВ «Софт»";  // статичне поле — спільне
    static count = 0;

    constructor(name) {
        this.name = name;           // поле екземпляра — власне
        Employee.count += 1;
    }
}
```

**C++**

```cpp
class Employee {
public:
    inline static std::string company = "ТОВ «Софт»";  // спільне
    inline static int count = 0;

    std::string name;               // поле екземпляра — власне

    explicit Employee(std::string name) : name(name) {
        ++count;
    }
};
```

| | Атрибут класу | Атрибут екземпляра |
|---|---|---|
| Скільки копій | одна на клас | по одній на об'єкт |
| Python | у тілі класу; `Employee.count` або `e.count` | в `__init__` через `self`; `e.name` |
| JavaScript | `static` у тілі класу; лише `Employee.count` | у `constructor` через `this`; `e.name` |
| C++ | `static` у тілі класу; `Employee::count` або `e.count` | поле в тілі класу; `e.name` |

**Пастка: читання і запис через екземпляр працюють по-різному.**

Коли ми **читаємо** `e1.company`, Python спершу шукає атрибут у самому
об'єкті, а якщо не знаходить — у класі. Тому `e1.company` повертає
спільне значення класу.

Коли ми **присвоюємо** `e1.company = ...`, Python у класі не шукає: запис
завжди йде в сам об'єкт. У `e1` з'являється власний атрибут `company`,
який «затінює» (закриває собою) атрибут класу — але лише для `e1`:

**Python**

```python
e1 = Employee("Коваль")
e2 = Employee("Бондар")
print(e1.company, e2.company)     # ТОВ «Софт» ТОВ «Софт» — обидва читають із класу

e1.company = "Інша"               # клас НЕ змінюється: у e1 з'являється власний атрибут

print(e1.company)                 # Інша       — власний атрибут e1
print(e2.company)                 # ТОВ «Софт» — e2 і далі читає з класу
print(Employee.company)           # ТОВ «Софт» — клас не змінився
```

Щоб змінити спільне значення для всіх, присвоюйте через клас:
`Employee.company = "Інша"`. Саме тому в конструкторі вище лічильник
збільшують як `Employee.count += 1`: варіант `self.count += 1` прочитав би
значення з класу, але записав би результат у власний атрибут об'єкта, і
спільний лічильник так і лишився б `0`.

У JavaScript статичне поле взагалі не видно через екземпляр
(`e1.company` — `undefined`), тож присвоєння просто додає до `e1` нове
звичайне поле, ніяк не пов'язане зі статичним. У C++ навпаки:
`e1.company` — лише інший запис того самого `Employee::company`, тож
присвоєння змінює спільне поле **для всіх** об'єктів:

**JavaScript**

```js
console.log(e1.company);          // undefined — статичне поле видно лише через клас
e1.company = "Інша";              // нове поле тільки в e1
console.log(Employee.company);    // ТОВ «Софт» — не змінилось
```

**C++**

```cpp
e1.company = "Інша";              // змінює СПІЛЬНЕ статичне поле!
std::cout << Employee::company;   // Інша
```

## 2.3 Методи екземпляра, класу та статичні

**Python**

```python
class Temperature:
    def __init__(self, celsius: float):
        self.celsius = celsius

    def to_fahrenheit(self) -> float:          # метод екземпляра (self)
        return self.celsius * 9 / 5 + 32

    @classmethod
    def from_fahrenheit(cls, f: float):        # метод класу (cls)
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_valid(celsius: float) -> bool:      # статичний (без self/cls)
        return celsius >= -273.15


t = Temperature.from_fahrenheit(212)           # 100.0 °C
```

**JavaScript**

```js
class Temperature {
    constructor(celsius) {
        this.celsius = celsius;
    }

    toFahrenheit() {                           // метод екземпляра (this)
        return this.celsius * 9 / 5 + 32;
    }

    static fromFahrenheit(f) {                 // статичний; this — сам клас
        return new this((f - 32) * 5 / 9);
    }

    static isValid(celsius) {
        return celsius >= -273.15;
    }
}

const t = Temperature.fromFahrenheit(212);     // 100 °C
```

**C++** — окремого «методу класу» немає, лише `static`:

```cpp
class Temperature {
public:
    explicit Temperature(double celsius) : celsius(celsius) {}

    double toFahrenheit() const {              // метод екземпляра (this)
        return celsius * 9 / 5 + 32;
    }

    static Temperature fromFahrenheit(double f) {   // статичний
        return Temperature((f - 32) * 5 / 9);
    }

    static bool isValid(double celsius) {
        return celsius >= -273.15;
    }

    double celsius;
};

Temperature t = Temperature::fromFahrenheit(212);   // 100 °C
```

| Вид | Перший параметр | Має доступ до | Типове призначення |
|-----|----------------|---------------|--------------------|
| звичайний | `self` | об'єкта й класу | робота з даними об'єкта |
| `@classmethod` | `cls` | класу | альтернативні конструктори |
| `@staticmethod` | немає | нічого | допоміжні функції, що логічно «живуть» у класі |

> **Різниця між мовами: виклик статичного методу.**
>
> ```python
> t.is_valid(5)            # працює: статичний метод доступний і через об'єкт
> ```
>
> ```js
> t.isValid(5);            // TypeError: t.isValid is not a function
> Temperature.isValid(5);  // правильно — лише через клас
> ```
>
> ```cpp
> t.isValid(5);            // працює, але прийнято писати Temperature::isValid(5)
> ```
>
> Ще одна пастка JS: клас не можна викликати без `new` —
> `Temperature(100)` кидає `TypeError: Class constructor Temperature
> cannot be invoked without 'new'`. У Python `new` не потрібне взагалі,
> у C++ `new` означає інше — виділення пам'яті в купі (див. розділ 8).

## 2.4 Альтернативні конструктори

Python не має перевантаження конструкторів. Замість цього —
`@classmethod`-«фабрики»:

**Python**

```python
class Date:
    def __init__(self, y, m, d):
        self.y, self.m, self.d = y, m, d

    @classmethod
    def from_string(cls, s: str):              # "2026-10-05"
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)
```

**JavaScript** — також лише один конструктор, тож використовують
статичні фабрики:

```js
class DateValue {
    constructor(y, m, d) {
        [this.y, this.m, this.d] = [y, m, d];
    }

    static fromString(s) {                     // "2026-10-05"
        const [y, m, d] = s.split("-").map(Number);
        return new this(y, m, d);
    }
}
```

**C++** — конструктори можна **перевантажувати**:

```cpp
#include <sstream>

class Date {
public:
    Date(int y, int m, int d) : y(y), m(m), d(d) {}

    explicit Date(const std::string& s) {      // "2026-10-05"
        char dash;
        std::istringstream in(s);
        in >> y >> dash >> m >> dash >> d;
    }

private:
    int y, m, d;
};
```

`cls` (а не жорстко `Date`) дозволяє підкласам теж користуватися фабрикою.

## 2.5 Ланцюжки викликів (fluent interface)

Якщо метод повертає `self`, виклики можна з'єднувати:

**Python**

```python
class Pizza:
    def __init__(self):
        self.toppings = []

    def add(self, t):
        self.toppings.append(t)
        return self                    # <- ключове

p = Pizza().add("сир").add("гриби").add("шинка")
```

**JavaScript**

```js
class Pizza {
    constructor() {
        this.toppings = [];
    }

    add(t) {
        this.toppings.push(t);
        return this;                   // <- ключове
    }
}

const p = new Pizza().add("сир").add("гриби").add("шинка");
```

**C++** — повертаємо **посилання** на `*this`, інакше кожен виклик
працюватиме з копією:

```cpp
class Pizza {
public:
    Pizza& add(const std::string& t) {
        toppings.push_back(t);
        return *this;                  // <- ключове
    }

private:
    std::vector<std::string> toppings;
};

Pizza p;
p.add("сир").add("гриби").add("шинка");
```

> **Пастка C++: «найнеприємніший розбір».** Порожні дужки при
> оголошенні змінної перетворюють її на оголошення **функції**:
>
> ```cpp
> Pizza p();               // це оголошення функції p, що повертає Pizza!
> p.add("сир");            // помилка компіляції
> Pizza q;                 // правильно
> Pizza r{};               // теж правильно
> ```
>
> У Python і JavaScript такої проблеми немає: `Pizza()` / `new Pizza()`
> завжди створюють об'єкт.

## 2.6 Порівняння з іншими мовами

| Задача | Python | JavaScript | C++ |
|--------|--------|-----------|-----|
| Значення за замовчуванням | `def f(x=0)` | `constructor(x = 0)` | `A(int x = 0)` |
| Атрибут класу | у тілі класу | `static count = 0;` | `static int count;` (+ визначення поза класом, або `inline`) |
| Метод класу | `@classmethod` | `static create()` | `static A create()` |
| Кілька конструкторів | фабрики | фабрики | **перевантаження** конструкторів |
