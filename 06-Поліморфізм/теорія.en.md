# Chapter 6. Polymorphism

## 6.1 The Idea

**Polymorphism** ("many forms") is the ability to work with objects of different types
through a **single interface**, without knowing their concrete class.

**Python**

```python
for shape in shapes:          # a mix of circles, squares, triangles
    print(shape.area())       # each shape computes its area its own way
```

**JavaScript**

```js
for (const shape of shapes) {         // a mix of circles, squares, triangles
    console.log(shape.area());        // each shape computes its area its own way
}
```

**C++** — polymorphism works through pointers/references to the base class:

```cpp
for (const auto& shape : shapes) {    // std::vector<std::unique_ptr<Shape>>
    std::cout << shape->area() << "\n";
}
```

The code that calls `area()` contains no `if type(...) == ...` branches —
adding a new shape does not require changing it. This implements the
**open/closed** principle.

## 6.2 Kinds of Polymorphism

| Kind | Essence | Example |
|------|---------|---------|
| Subtype | children override the parent's method | `Shape.area()` |
| Duck typing | only the presence of methods matters | any object with `quote()` |
| Ad hoc | one name — different behavior depending on the argument type | `len()`, `+`, `singledispatch`, overloading in C++ |
| Parametric | code works with any data type | `list[T]`, C++ templates |

## 6.3 Subtype Polymorphism

**Python**

```python
class Shape:
    def area(self): raise NotImplementedError

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r ** 2

class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2


def total_area(shapes: list[Shape]) -> float:
    return sum(s.area() for s in shapes)     # knows nothing about Circle/Square
```

**JavaScript**

```js
class Shape {
    area() { throw new Error("not implemented"); }
}

class Circle extends Shape {
    constructor(r) { super(); this.r = r; }
    area() { return Math.PI * this.r ** 2; }
}

class Square extends Shape {
    constructor(a) { super(); this.a = a; }
    area() { return this.a ** 2; }
}

function totalArea(shapes) {
    return shapes.reduce((sum, s) => sum + s.area(), 0);   // knows nothing about Circle/Square
}
```

**C++**

```cpp
#include <cmath>
#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r(r) {}
    double area() const override { return M_PI * r * r; }
private:
    double r;
};

class Square : public Shape {
public:
    explicit Square(double a) : a(a) {}
    double area() const override { return a * a; }
private:
    double a;
};

double totalArea(const std::vector<std::unique_ptr<Shape>>& shapes) {
    double sum = 0;
    for (const auto& s : shapes) sum += s->area();   // knows nothing about Circle/Square
    return sum;
}
```

The call `s.area()` picks the implementation **at run time** based on the real
type of `s` — this is **late (dynamic) binding**.

## 6.4 Duck Typing

> "If it walks like a duck and quacks like a duck, it's a duck."

Python does not require a common ancestor:

**Python**

```python
class Duck:
    def quote(self):  return "Quack!"

class Robot:
    def quote(self):  return "Beep-boop"

def talk(obj):
    print(obj.quote())      # only the quote() method is needed
```

**JavaScript** — duck typing works the same way:

```js
class Duck  { quote() { return "Quack!"; } }
class Robot { quote() { return "Beep-boop"; } }

function talk(obj) {
    console.log(obj.quote());   // only the quote() method is needed
}
```

**C++** — "duck" typing comes from **templates** (checked at compile
time), and since C++20 the requirement can be written as a concept:

```cpp
#include <concepts>

struct Duck  { std::string quote() const { return "Quack!"; } };
struct Robot { std::string quote() const { return "Beep-boop"; } };

template <typename T>
concept Quoter = requires(const T& t) {
    { t.quote() } -> std::convertible_to<std::string>;
};

void talk(const Quoter auto& obj) {
    std::cout << obj.quote() << "\n";   // only the quote() method is needed
}
```

The upside is flexibility. The downside is that an error (`AttributeError`) shows up only
at run time. Safeguards: `typing.Protocol` (a formal "interface"
for static checks), `hasattr`, `try/except`.

> **Language difference: when it turns out the method is missing.**
>
> ```python
> talk(42)                 # AttributeError: 'int' object has no attribute 'quote'
> ```
>
> ```js
> talk(42);                // TypeError: obj.quote is not a function
> ```
>
> ```cpp
> talk(42);                // COMPILE error: int does not satisfy the Quoter concept
> ```
>
> In Python and JS the error happens at run time — and only if the
> program actually reaches this call. C++ templates check "duck" typing
> before the program runs.

## 6.5 Ad Hoc Polymorphism

Python has no **overloading** by argument type/count
(the last definition "overrides" the previous ones). Substitutes:

**Python**

```python
# 1) *args
def add(*numbers): return sum(numbers)

# 2) an explicit type check
def describe(x):
    if isinstance(x, int): return "integer"

# 3) functools.singledispatch — by the type of the first argument
from functools import singledispatch

@singledispatch
def show(x): return f"object {x}"

@show.register
def _(x: int): return f"integer {x}"

@show.register
def _(x: list): return f"list of {len(x)} items"
```

**JavaScript** — has no overloading either; rest parameters and type
checks are used instead:

```js
function add(...numbers) { return numbers.reduce((a, b) => a + b, 0); }

function show(x) {
    if (Number.isInteger(x)) return `integer ${x}`;
    if (Array.isArray(x))    return `list of ${x.length} items`;
    return `object ${x}`;
}
```

**C++** — **real overloading**: the compiler picks the function by the
argument types:

```cpp
#include <string>
#include <vector>

std::string show(int x)                     { return "integer " + std::to_string(x); }
std::string show(const std::vector<int>& x) {
    return "list of " + std::to_string(x.size()) + " items";
}
std::string show(const std::string& x)      { return "object " + x; }

show(5);                    // integer 5
show(std::vector{1, 2});    // list of 2 items
```

Built-in examples: `len(x)` works with strings, lists, dictionaries;
`+` adds numbers and concatenates strings and lists.

> **Language difference: two functions with the same name.**
>
> ```python
> def area(r): ...
> def area(w, h): ...      # silently REPLACES the previous one
> area(5)                  # TypeError: missing 1 required positional argument: 'h'
> ```
>
> ```js
> function area(r) {}
> function area(w, h) {}   // also replaced without a warning; area(5) → h === undefined
> ```
>
> ```cpp
> double area(double r);
> double area(double w, double h);   // TWO different functions — overloading
> area(5);                            // the first one is called
> ```

## 6.6 Parametric Polymorphism

Code that does not depend on the concrete element type:

**Python**

```python
def largest(items):
    return max(items)          # numbers, strings, custom classes with __lt__

from typing import Generic, TypeVar
T = TypeVar("T")

class Box(Generic[T]):
    def __init__(self, item: T): self.item = item
```

**JavaScript** — dynamic typing gives parametricity "for free":

```js
function largest(items) {
    return items.reduce((a, b) => (b > a ? b : a));
}

class Box {
    constructor(item) { this.item = item; }
}
```

**C++** — templates:

```cpp
#include <algorithm>
#include <vector>

template <typename T>
T largest(const std::vector<T>& items) {
    return *std::max_element(items.begin(), items.end());  // needs operator<
}

template <typename T>
class Box {
public:
    explicit Box(T item) : item(item) {}
    T item;
};
```

## 6.7 Polymorphism and the Contract

Polymorphism works only when children honor the parent's contract
(the Liskov principle, chapter 5). It is worth **documenting** the shared interface
with a base class, a `Protocol`, or an abstract class
(chapter 7).

## 6.8 Comparison with Other Languages

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Subtypes | any method is "virtual" | the same | the `virtual` keyword is required |
| Duck typing | yes | yes | via templates (compile-time) |
| Overloading | none (`singledispatch`) | none | **yes** (`f(int)`, `f(string)`) |
| Parametric | `Generic`, dynamic typing | dynamic typing | `template<class T>` |

A typical C++ mistake: without `virtual`, a call through a pointer or reference
to the base class invokes the **base** version (static binding) —
polymorphism "does not kick in".
