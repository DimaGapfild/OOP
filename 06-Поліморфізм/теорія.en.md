# Chapter 6. Polymorphism

## 6.1 The Idea

**Polymorphism** ("many forms") is the ability to work with objects of different types
through a **single interface**, without knowing their concrete class.

```python
for shape in shapes:          # a mix of circles, squares, triangles
    print(shape.area())       # each shape computes its area its own way
```

The code that calls `area()` contains no `if type(...) == ...` branches —
adding a new shape does not require changing it. This implements the
**open/closed** principle.

## 6.2 Kinds of Polymorphism

| Kind | Essence | Example |
|------|---------|---------|
| Subtype | children override the parent's method | `Shape.area()` |
| Duck typing | only the presence of methods matters | any object with `quote()` |
| Ad hoc | one name — different behavior depending on the argument type | `len()`, `+`, `singledispatch`, overloading in C++ |
| Parametric | code works with any data type | `list[T]`, C++ templates |

## 6.3 Subtype Polymorphism

```python
class Shape:
    def area(self): raise NotImplementedError

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r ** 2

class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2


def total_area(shapes: list[Shape]) -> float:
    return sum(s.area() for s in shapes)     # knows nothing about Circle/Square
```

The call `s.area()` picks the implementation **at run time** based on the real
type of `s` — this is **late (dynamic) binding**.

## 6.4 Duck Typing

> "If it walks like a duck and quacks like a duck, it's a duck."

Python does not require a common ancestor:

```python
class Duck:
    def quote(self):  return "Quack!"

class Robot:
    def quote(self):  return "Beep-boop"

def talk(obj):
    print(obj.quote())      # only the quote() method is needed
```

The upside is flexibility. The downside is that an error (`AttributeError`) shows up only
at run time. Safeguards: `typing.Protocol` (a formal "interface"
for static checks), `hasattr`, `try/except`.

## 6.5 Ad Hoc Polymorphism

Python has no **overloading** by argument type/count
(the last definition "overrides" the previous ones). Substitutes:

```python
# 1) *args
def add(*numbers): return sum(numbers)

# 2) an explicit type check
def describe(x):
    if isinstance(x, int): return "integer"

# 3) functools.singledispatch — by the type of the first argument
from functools import singledispatch

@singledispatch
def show(x): return f"object {x}"

@show.register
def _(x: int): return f"integer {x}"

@show.register
def _(x: list): return f"list of {len(x)} items"
```

Built-in examples: `len(x)` works with strings, lists, dictionaries;
`+` adds numbers and concatenates strings and lists.

## 6.6 Parametric Polymorphism

Code that does not depend on the concrete element type:

```python
def largest(items):
    return max(items)          # numbers, strings, custom classes with __lt__

from typing import Generic, TypeVar
T = TypeVar("T")

class Box(Generic[T]):
    def __init__(self, item: T): self.item = item
```

## 6.7 Polymorphism and the Contract

Polymorphism works only when children honor the parent's contract
(the Liskov principle, chapter 5). It is worth **documenting** the shared interface
with a base class, a `Protocol`, or an abstract class
(chapter 7).

## 6.8 Comparison with Other Languages

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Subtypes | any method is "virtual" | the same | the `virtual` keyword is required |
| Duck typing | yes | yes | via templates (compile-time) |
| Overloading | none (`singledispatch`) | none | **yes** (`f(int)`, `f(string)`) |
| Parametric | `Generic`, dynamic typing | dynamic typing | `template<class T>` |

A typical C++ mistake: without `virtual`, a call through a pointer or reference
to the base class invokes the **base** version (static binding) —
polymorphism "does not kick in".
