# Розділ 6. Поліморфізм

## 6.1 Ідея

**Поліморфізм** («багато форм») — здатність працювати з різними типами
об'єктів через **єдиний інтерфейс**, не знаючи їхнього конкретного класу.

```python
for shape in shapes:          # суміш кіл, квадратів, трикутників
    print(shape.area())       # кожна фігура рахує площу по-своєму
```

Код, що викликає `area()`, не містить розгалужень `if type(...) == ...` —
додавання нової фігури не вимагає його змінювати. Це реалізація
принципу **відкритості/закритості** (open/closed).

## 6.2 Види поліморфізму

| Вид | Суть | Приклад |
|-----|------|---------|
| Підтипів (subtype) | нащадки перевизначають метод предка | `Shape.area()` |
| «Качина» типізація (duck typing) | важить лише наявність методів | будь-який об'єкт із `quote()` |
| Ситуативний (ad hoc) | одна назва — різна поведінка за типом аргумента | `len()`, `+`, `singledispatch`, перевантаження в C++ |
| Параметричний | код працює з будь-яким типом даних | `list[T]`, шаблони C++ |

## 6.3 Поліморфізм підтипів

```python
class Shape:
    def area(self): raise NotImplementedError

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r ** 2

class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2


def total_area(shapes: list[Shape]) -> float:
    return sum(s.area() for s in shapes)     # не знає про Circle/Square
```

Виклик `s.area()` вибирає реалізацію **під час виконання** за реальним
типом `s` — це **пізнє (динамічне) зв'язування**.

## 6.4 Duck typing

> «Якщо воно ходить як качка і крякає як качка — це качка».

Python не вимагає спільного предка:

```python
class Duck:
    def quote(self):  return "Кря!"

class Robot:
    def quote(self):  return "Біп-буп"

def talk(obj):
    print(obj.quote())      # потрібен лише метод quote()
```

Плюс — гнучкість. Мінус — помилка (`AttributeError`) виявиться лише
під час виконання. Захист: `typing.Protocol` (формальний «інтерфейс»
для статичних перевірок), `hasattr`, `try/except`.

## 6.5 Ситуативний поліморфізм

**Перевантаження** за типом/кількістю аргументів у Python немає
(останнє визначення «перекриває» попередні). Заміни:

```python
# 1) *args
def add(*numbers): return sum(numbers)

# 2) явна перевірка типу
def describe(x):
    if isinstance(x, int): return "ціле"

# 3) functools.singledispatch — за типом першого аргумента
from functools import singledispatch

@singledispatch
def show(x): return f"об'єкт {x}"

@show.register
def _(x: int): return f"ціле {x}"

@show.register
def _(x: list): return f"список із {len(x)} елементів"
```

Вбудовані приклади: `len(x)` працює з рядками, списками, словниками;
`+` складає числа, склеює рядки й списки.

## 6.6 Параметричний поліморфізм

Код, що не залежить від конкретного типу елементів:

```python
def largest(items):
    return max(items)          # числа, рядки, власні класи з __lt__

from typing import Generic, TypeVar
T = TypeVar("T")

class Box(Generic[T]):
    def __init__(self, item: T): self.item = item
```

## 6.7 Поліморфізм і контракт

Поліморфізм працює лише тоді, коли нащадки дотримуються контракту
предка (принцип Лісков, розділ 5). Спільний інтерфейс варто
**документувати** — базовим класом, `Protocol` або абстрактним класом
(розділ 7).

## 6.8 Порівняння з іншими мовами

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Підтипи | будь-який метод «віртуальний» | так само | потрібне слово `virtual` |
| Duck typing | так | так | через шаблони (compile-time) |
| Перевантаження | немає (`singledispatch`) | немає | **є** (`f(int)`, `f(string)`) |
| Параметричний | `Generic`, динамічна типізація | динамічна типізація | `template<class T>` |

Типова помилка C++: без `virtual` виклик через вказівник чи посилання
на базовий клас викличе **базову** версію (статичне зв'язування) —
поліморфізм «не спрацює».
