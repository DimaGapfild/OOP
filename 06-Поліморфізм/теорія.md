# Розділ 6. Поліморфізм

## 6.1 Ідея

**Поліморфізм** («багато форм») — здатність працювати з різними типами
об'єктів через **єдиний інтерфейс**, не знаючи їхнього конкретного класу.

**Python**

```python
for shape in shapes:          # суміш кіл, квадратів, трикутників
    print(shape.area())       # кожна фігура рахує площу по-своєму
```

**JavaScript**

```js
for (const shape of shapes) {         // суміш кіл, квадратів, трикутників
    console.log(shape.area());        // кожна фігура рахує площу по-своєму
}
```

**C++** — поліморфізм працює через вказівники/посилання на базовий клас:

```cpp
for (const auto& shape : shapes) {    // std::vector<std::unique_ptr<Shape>>
    std::cout << shape->area() << "\n";
}
```

Код, що викликає `area()`, не містить розгалужень `if type(...) == ...` —
додавання нової фігури не вимагає його змінювати. Це реалізація
принципу **відкритості/закритості** (open/closed).

## 6.2 Види поліморфізму

| Вид | Суть | Приклад |
|-----|------|---------|
| Підтипів (subtype) | нащадки перевизначають метод предка | `Shape.area()` |
| «Качина» типізація (duck typing) | важить лише наявність методів | будь-який об'єкт із `quote()` |
| Ситуативний (ad hoc) | одна назва — різна поведінка за типом аргумента | `len()`, `+`, `singledispatch`, перевантаження в C++ |
| Параметричний | код працює з будь-яким типом даних | `list[T]`, шаблони C++ |

## 6.3 Поліморфізм підтипів

**Python**

```python
class Shape:
    def area(self): raise NotImplementedError

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r ** 2

class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2


def total_area(shapes: list[Shape]) -> float:
    return sum(s.area() for s in shapes)     # не знає про Circle/Square
```

**JavaScript**

```js
class Shape {
    area() { throw new Error("not implemented"); }
}

class Circle extends Shape {
    constructor(r) { super(); this.r = r; }
    area() { return Math.PI * this.r ** 2; }
}

class Square extends Shape {
    constructor(a) { super(); this.a = a; }
    area() { return this.a ** 2; }
}

function totalArea(shapes) {
    return shapes.reduce((sum, s) => sum + s.area(), 0);   // не знає про Circle/Square
}
```

**C++**

```cpp
#include <cmath>
#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r(r) {}
    double area() const override { return M_PI * r * r; }
private:
    double r;
};

class Square : public Shape {
public:
    explicit Square(double a) : a(a) {}
    double area() const override { return a * a; }
private:
    double a;
};

double totalArea(const std::vector<std::unique_ptr<Shape>>& shapes) {
    double sum = 0;
    for (const auto& s : shapes) sum += s->area();   // не знає про Circle/Square
    return sum;
}
```

Виклик `s.area()` вибирає реалізацію **під час виконання** за реальним
типом `s` — це **пізнє (динамічне) зв'язування**.

## 6.4 Duck typing

> «Якщо воно ходить як качка і крякає як качка — це качка».

Python не вимагає спільного предка:

**Python**

```python
class Duck:
    def quote(self):  return "Кря!"

class Robot:
    def quote(self):  return "Біп-буп"

def talk(obj):
    print(obj.quote())      # потрібен лише метод quote()
```

**JavaScript** — duck typing працює так само:

```js
class Duck  { quote() { return "Кря!"; } }
class Robot { quote() { return "Біп-буп"; } }

function talk(obj) {
    console.log(obj.quote());   // потрібен лише метод quote()
}
```

**C++** — «качину» типізацію дають **шаблони** (перевірка під час
компіляції), а з C++20 вимогу можна записати концептом:

```cpp
#include <concepts>

struct Duck  { std::string quote() const { return "Кря!"; } };
struct Robot { std::string quote() const { return "Біп-буп"; } };

template <typename T>
concept Quoter = requires(const T& t) {
    { t.quote() } -> std::convertible_to<std::string>;
};

void talk(const Quoter auto& obj) {
    std::cout << obj.quote() << "\n";   // потрібен лише метод quote()
}
```

Плюс — гнучкість. Мінус — помилка (`AttributeError`) виявиться лише
під час виконання. Захист: `typing.Protocol` (формальний «інтерфейс»
для статичних перевірок), `hasattr`, `try/except`.

> **Різниця між мовами: коли виявиться, що методу немає.**
>
> ```python
> talk(42)                 # AttributeError: 'int' object has no attribute 'quote'
> ```
>
> ```js
> talk(42);                // TypeError: obj.quote is not a function
> ```
>
> ```cpp
> talk(42);                // помилка КОМПІЛЯЦІЇ: int не задовольняє концепт Quoter
> ```
>
> У Python і JS помилка виникне під час виконання — і лише якщо програма
> дійде саме до цього виклику. Шаблони C++ перевіряють «качину»
> типізацію до запуску.

## 6.5 Ситуативний поліморфізм

**Перевантаження** за типом/кількістю аргументів у Python немає
(останнє визначення «перекриває» попередні). Заміни:

**Python**

```python
# 1) *args
def add(*numbers): return sum(numbers)

# 2) явна перевірка типу
def describe(x):
    if isinstance(x, int): return "ціле"

# 3) functools.singledispatch — за типом першого аргумента
from functools import singledispatch

@singledispatch
def show(x): return f"об'єкт {x}"

@show.register
def _(x: int): return f"ціле {x}"

@show.register
def _(x: list): return f"список із {len(x)} елементів"
```

**JavaScript** — перевантаження теж немає; замінюють залишковими
параметрами та перевіркою типу:

```js
function add(...numbers) { return numbers.reduce((a, b) => a + b, 0); }

function show(x) {
    if (Number.isInteger(x)) return `ціле ${x}`;
    if (Array.isArray(x))    return `список із ${x.length} елементів`;
    return `об'єкт ${x}`;
}
```

**C++** — **справжнє перевантаження**: компілятор обирає функцію за
типами аргументів:

```cpp
#include <string>
#include <vector>

std::string show(int x)                     { return "ціле " + std::to_string(x); }
std::string show(const std::vector<int>& x) {
    return "список із " + std::to_string(x.size()) + " елементів";
}
std::string show(const std::string& x)      { return "об'єкт " + x; }

show(5);                    // ціле 5
show(std::vector{1, 2});    // список із 2 елементів
```

Вбудовані приклади: `len(x)` працює з рядками, списками, словниками;
`+` складає числа, склеює рядки й списки.

> **Різниця між мовами: дві функції з однаковою назвою.**
>
> ```python
> def area(r): ...
> def area(w, h): ...      # мовчки ЗАМІНЮЄ попередню
> area(5)                  # TypeError: missing 1 required positional argument: 'h'
> ```
>
> ```js
> function area(r) {}
> function area(w, h) {}   // теж заміна без попередження; area(5) → h === undefined
> ```
>
> ```cpp
> double area(double r);
> double area(double w, double h);   // ДВІ різні функції — перевантаження
> area(5);                            // викличеться перша
> ```

## 6.6 Параметричний поліморфізм

Код, що не залежить від конкретного типу елементів:

**Python**

```python
def largest(items):
    return max(items)          # числа, рядки, власні класи з __lt__

from typing import Generic, TypeVar
T = TypeVar("T")

class Box(Generic[T]):
    def __init__(self, item: T): self.item = item
```

**JavaScript** — динамічна типізація дає параметричність «безкоштовно»:

```js
function largest(items) {
    return items.reduce((a, b) => (b > a ? b : a));
}

class Box {
    constructor(item) { this.item = item; }
}
```

**C++** — шаблони:

```cpp
#include <algorithm>
#include <vector>

template <typename T>
T largest(const std::vector<T>& items) {
    return *std::max_element(items.begin(), items.end());  // потрібен operator<
}

template <typename T>
class Box {
public:
    explicit Box(T item) : item(item) {}
    T item;
};
```

## 6.7 Поліморфізм і контракт

Поліморфізм працює лише тоді, коли нащадки дотримуються контракту
предка (принцип Лісков, розділ 5). Спільний інтерфейс варто
**документувати** — базовим класом, `Protocol` або абстрактним класом
(розділ 7).

## 6.8 Порівняння з іншими мовами

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Підтипи | будь-який метод «віртуальний» | так само | потрібне слово `virtual` |
| Duck typing | так | так | через шаблони (compile-time) |
| Перевантаження | немає (`singledispatch`) | немає | **є** (`f(int)`, `f(string)`) |
| Параметричний | `Generic`, динамічна типізація | динамічна типізація | `template<class T>` |

Типова помилка C++: без `virtual` виклик через вказівник чи посилання
на базовий клас викличе **базову** версію (статичне зв'язування) —
поліморфізм «не спрацює».
