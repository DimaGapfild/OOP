# Розділ 1. Класи та об'єкти

## 1.1 Навіщо потрібне ООП

У процедурному підході **дані окремо, функції окремо**:

**Python**

```python
book = {"title": "Кобзар", "pages": 320}

def is_long(b):
    return b["pages"] > 300
```

**JavaScript**

```js
const book = { title: "Кобзар", pages: 320 };

function isLong(b) {
    return b.pages > 300;
}
```

**C++**

```cpp
struct BookData { std::string title; int pages; };

bool isLong(const BookData& b) {
    return b.pages > 300;
}
```

Нічого не гарантує, що в словнику є ключ `pages`, а функція `is_long`
ніяк не прив'язана до «книжки». ООП **об'єднує дані й поведінку**
в одну сутність — **об'єкт**.

Переваги підходу:

- код моделює предметну область (студент, рахунок, фігура);
- дані захищені від довільних змін;
- легко повторно використовувати й розширювати код;
- великі програми діляться на невеликі незалежні частини.

## 1.2 Клас і об'єкт

- **Клас** — опис (шаблон, тип): які дані має сутність і що вона вміє.
- **Об'єкт (екземпляр)** — конкретне втілення класу з власними даними.

Аналогія: клас — креслення будинку, об'єкт — збудований будинок.
За одним кресленням можна збудувати багато будинків.

| Поняття | Що це | Приклад |
|---------|-------|---------|
| Клас | тип даних | `Book` |
| Об'єкт | екземпляр класу | `Book("Кобзар", 320)` |
| Атрибут (поле) | дані об'єкта | `title`, `pages` |
| Метод | функція, що належить класу | `is_long()` |

## 1.3 Мінімальний клас

**Python**

```python
class Book:
    """Книга з назвою та кількістю сторінок."""

    def __init__(self, title: str, pages: int):
        self.title = title
        self.pages = pages

    def is_long(self) -> bool:
        return self.pages > 300


b1 = Book("Кобзар", 320)
b2 = Book("Енеїда", 180)
print(b1.title, b1.is_long())   # Кобзар True
print(b2.title, b2.is_long())   # Енеїда False
```

**JavaScript**

```js
/** Книга з назвою та кількістю сторінок. */
class Book {
    constructor(title, pages) {
        this.title = title;
        this.pages = pages;
    }

    isLong() {
        return this.pages > 300;
    }
}

const b1 = new Book("Кобзар", 320);
const b2 = new Book("Енеїда", 180);
console.log(b1.title, b1.isLong());   // Кобзар true
console.log(b2.title, b2.isLong());   // Енеїда false
```

**C++**

```cpp
#include <iostream>
#include <string>

// Книга з назвою та кількістю сторінок.
class Book {
public:
    std::string title;
    int pages;

    Book(std::string title, int pages) : title(title), pages(pages) {}

    bool isLong() const {
        return pages > 300;
    }
};

int main() {
    Book b1("Кобзар", 320);
    Book b2("Енеїда", 180);
    std::cout << b1.title << " " << b1.isLong() << "\n";   // Кобзар 1
    std::cout << b2.title << " " << b2.isLong() << "\n";   // Енеїда 0
}
```

Кожен об'єкт має **власний набір атрибутів**: зміна `b1.pages` не
впливає на `b2`.

**Python**

```python
b1.pages = 100
print(b1.is_long(), b2.pages)   # False 180
```

**JavaScript**

```js
b1.pages = 100;
console.log(b1.isLong(), b2.pages);   // false 180
```

**C++**

```cpp
b1.pages = 100;
std::cout << b1.isLong() << " " << b2.pages << "\n";   // 0 180
```

> **Різниця між мовами: неправильна кількість аргументів.**
> Що станеться, якщо передати в конструктор лише один параметр?
>
> ```python
> b = Book("Кобзар")       # TypeError: missing 1 required positional argument
> ```
>
> ```js
> const b = new Book("Кобзар");   // помилки НЕМАЄ: pages === undefined
> b.isLong();                     // false — бо undefined > 300 дає false
> ```
>
> ```cpp
> Book b("Кобзар");        // помилка КОМПІЛЯЦІЇ: no matching constructor
> ```
>
> | | Python | JavaScript | C++ |
> |---|---|---|---|
> | Забракло аргументів | `TypeError` під час виконання | мовчки `undefined` | помилка компіляції |
> | Зайві аргументи | `TypeError` під час виконання | мовчки ігноруються | помилка компіляції |
> | Коли помилка помітна | коли виконується **цей рядок** | можливо, ніколи (хибний результат) | **до запуску** програми |
>
> Python не компілює програму наперед: якщо рядок `Book("Кобзар")`
> стоїть у функції, яку жодного разу не викликали, помилки не буде.
> У JavaScript помилка найпідступніша: об'єкт створюється «зламаним»,
> а наслідки проявляються деінде. Тому в JS параметри варто перевіряти
> в конструкторі явно.

> **Різниця між мовами: нові атрибути й описки.** У Python і JavaScript
> об'єктові можна присвоїти атрибут, якого немає в класі, — і описка
> мовчки створить новий атрибут:
>
> ```python
> b1.pagse = 100           # описка: створено НОВИЙ атрибут, pages не змінився
> ```
>
> ```js
> b1.pagse = 100;          // так само — без помилки
> ```
>
> ```cpp
> b1.pagse = 100;          // помилка компіляції: no member named 'pagse'
> ```
>
> У C++ набір полів фіксований оголошенням класу.

## 1.4 Посилання на поточний об'єкт

`self` — посилання на **поточний об'єкт**. Це перший параметр кожного
методу; при виклику Python підставляє його сам:

**Python**

```python
b1.is_long()            # те саме, що Book.is_long(b1)
```

У JavaScript роль `self` виконує `this`, у C++ — `this` (вказівник),
але обидві мови передають його **неявно** — у списку параметрів його немає:

**JavaScript**

```js
b1.isLong();            // усередині методу this === b1
```

**C++**

```cpp
b1.isLong();            // усередині методу this == &b1
```

> **Різниця між мовами: «загублений» `this`.** У Python метод,
> узятий з об'єкта, пам'ятає свій об'єкт (`f = b1.is_long; f()` працює).
> У JavaScript — ні: `this` визначається **в момент виклику**:
>
> ```js
> const f = b1.isLong;
> f();                     // TypeError: Cannot read properties of undefined
> setTimeout(b1.isLong, 0);       // та сама проблема з колбеками
> setTimeout(() => b1.isLong(), 0);   // правильно: стрілкова функція
> ```
>
> У C++ так «відірвати» метод від об'єкта не можна: вказівник на метод
> (`&Book::isLong`) викликається лише разом з об'єктом — `(b1.*f)()`.
>
> Ще одна відмінність: у Python `self` у методі пишуть **обов'язково**
> (`self.pages`), у JS — `this.pages` (без `this` — звернення до
> неіснуючої змінної, `ReferenceError`), а в C++ `this->` можна
> пропускати: `pages` усередині методу і є полем.

## 1.5 Об'єкти — посилання

Змінна зберігає **посилання** на об'єкт, а не сам об'єкт.

**Python**

```python
a = Book("Кобзар", 320)
b = a                    # b вказує на ТОЙ САМИЙ об'єкт
b.pages = 1
print(a.pages)           # 1
print(a is b)            # True — той самий об'єкт
c = Book("Кобзар", 1)
print(a is c)            # False — різні об'єкти (хоч дані однакові)
```

**JavaScript**

```js
const a = new Book("Кобзар", 320);
const b = a;                     // b вказує на ТОЙ САМИЙ об'єкт
b.pages = 1;
console.log(a.pages);            // 1
console.log(a === b);            // true — той самий об'єкт
const c = new Book("Кобзар", 1);
console.log(a === c);            // false — різні об'єкти
```

**C++** — тут об'єкти за замовчуванням є **значеннями**, посилання
треба оголошувати явно:

```cpp
Book a("Кобзар", 320);
Book& b = a;                     // b — посилання на ТОЙ САМИЙ об'єкт
b.pages = 1;
std::cout << a.pages << "\n";    // 1
std::cout << (&a == &b) << "\n"; // 1 — та сама адреса
Book c = a;                      // c — КОПІЯ, окремий об'єкт
std::cout << (&a == &c) << "\n"; // 0
```

Щоб отримати незалежну копію — створюють новий об'єкт
(або `copy.copy`, `copy.deepcopy`).

> **Різниця між мовами: що порівнює `==`.**
>
> | | Python | JavaScript | C++ |
> |---|---|---|---|
> | `a == b` для об'єктів | викликає `__eq__`; за замовчуванням — чи це той самий об'єкт | `==` і `===` завжди порівнюють **посилання** | помилка компіляції, поки не визначено `operator==` |
> | «Той самий об'єкт?» | `a is b` | `a === b` | `&a == &b` |
>
> Тому в JS `new Book("Кобзар", 1) == new Book("Кобзар", 1)` — це
> `false`, і змінити це неможливо: для порівняння за значенням пишуть
> власний метод `equals()`.

## 1.6 Функції для роботи з об'єктами

**Python**

```python
type(b1)                     # <class '__main__.Book'>
isinstance(b1, Book)         # True
hasattr(b1, "title")         # True
getattr(b1, "pages")         # 320
vars(b1)                     # {'title': 'Кобзар', 'pages': 320}
```

**JavaScript**

```js
typeof b1;                       // "object"
b1.constructor.name;             // "Book"
b1 instanceof Book;              // true
"title" in b1;                   // true
b1["pages"];                     // 320
Object.entries(b1);              // [["title", "Кобзар"], ["pages", 320]]
```

**C++** — більшість перевірок відбувається **під час компіляції**;
під час виконання доступна лише інформація про тип:

```cpp
#include <typeinfo>

typeid(b1).name();               // ім'я типу (залежить від компілятора)
Book* p = &b1;                   // тип перевіряє компілятор
// hasattr / getattr / vars — аналогів немає: поля відомі статично
```

> **Різниця між мовами: звернення до неіснуючого атрибута.**
>
> ```python
> b1.color                 # AttributeError: 'Book' object has no attribute 'color'
> ```
>
> ```js
> b1.color;                // undefined — без помилки
> ```
>
> ```cpp
> b1.color;                // помилка компіляції
> ```

## 1.7 Об'єкти в об'єктах

Атрибут може бути іншим об'єктом — так будують складніші моделі:

**Python**

```python
class Library:
    def __init__(self):
        self.books: list[Book] = []

    def add(self, book: Book) -> None:
        self.books.append(book)

    def total_pages(self) -> int:
        return sum(b.pages for b in self.books)
```

**JavaScript**

```js
class Library {
    constructor() {
        this.books = [];
    }

    add(book) {
        this.books.push(book);
    }

    totalPages() {
        return this.books.reduce((sum, b) => sum + b.pages, 0);
    }
}
```

**C++**

```cpp
#include <vector>

class Library {
public:
    void add(const Book& book) {
        books.push_back(book);
    }

    int totalPages() const {
        int sum = 0;
        for (const Book& b : books) sum += b.pages;
        return sum;
    }

private:
    std::vector<Book> books;
};
```

## 1.8 Порівняння з іншими мовами

| Python | JavaScript | C++ |
|--------|-----------|-----|
| `class A:` | `class A {` | `class A { public: ... };` |
| `__init__(self)` | `constructor()` | `A() {}` |
| `self.x` | `this.x` | `this->x` або `x` |
| `A(1)` | `new A(1)` | `A a(1);` |
| `b = a` (посилання) | `b = a` (посилання) | `A b = a;` — **копія**! |

У C++ присвоєння об'єкта створює копію; посилання потребує `A& b = a;`
або вказівника.
