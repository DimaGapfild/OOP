# Chapter 1. Classes and Objects

## 1.1 Why OOP

In the procedural approach, **data and functions are kept apart**:

```python
book = {"title": "Kobzar", "pages": 320}

def is_long(b):
    return b["pages"] > 300
```

Nothing guarantees that the dictionary has a `pages` key, and the function
`is_long` is in no way tied to a "book". OOP **combines data and behavior**
into a single entity — an **object**.

Advantages of this approach:

- the code models the problem domain (student, account, shape);
- data is protected from arbitrary changes;
- code is easy to reuse and extend;
- large programs are split into small independent parts.

## 1.2 Class and Object

- A **class** is a description (template, type): what data an entity has and what it can do.
- An **object (instance)** is a concrete realization of a class with its own data.

Analogy: a class is a house blueprint, an object is a house that has been built.
Many houses can be built from one blueprint.

| Concept | What it is | Example |
|---------|-----------|---------|
| Class | a data type | `Book` |
| Object | an instance of a class | `Book("Kobzar", 320)` |
| Attribute (field) | the object's data | `title`, `pages` |
| Method | a function that belongs to a class | `is_long()` |

## 1.3 A Minimal Class

```python
class Book:
    """A book with a title and a page count."""

    def __init__(self, title: str, pages: int):
        self.title = title
        self.pages = pages

    def is_long(self) -> bool:
        return self.pages > 300


b1 = Book("Kobzar", 320)
b2 = Book("Eneida", 180)
print(b1.title, b1.is_long())   # Kobzar True
print(b2.title, b2.is_long())   # Eneida False
```

Every object has **its own set of attributes**: changing `b1.pages` does not
affect `b2`.

```python
b1.pages = 100
print(b1.is_long(), b2.pages)   # False 180
```

## 1.4 self

`self` is a reference to the **current object**. It is the first parameter of every
method; when a method is called, Python supplies it automatically:

```python
b1.is_long()            # the same as Book.is_long(b1)
```

## 1.5 Objects Are References

A variable stores a **reference** to an object, not the object itself.

```python
a = Book("Kobzar", 320)
b = a                    # b points to the SAME object
b.pages = 1
print(a.pages)           # 1
print(a is b)            # True — the same object
c = Book("Kobzar", 1)
print(a is c)            # False — different objects (even though the data is equal)
```

To get an independent copy, create a new object
(or use `copy.copy`, `copy.deepcopy`).

## 1.6 Functions for Working with Objects

```python
type(b1)                     # <class '__main__.Book'>
isinstance(b1, Book)         # True
hasattr(b1, "title")         # True
getattr(b1, "pages")         # 320
vars(b1)                     # {'title': 'Kobzar', 'pages': 320}
```

## 1.7 Objects Inside Objects

An attribute can be another object — this is how more complex models are built:

```python
class Library:
    def __init__(self):
        self.books: list[Book] = []

    def add(self, book: Book) -> None:
        self.books.append(book)

    def total_pages(self) -> int:
        return sum(b.pages for b in self.books)
```

## 1.8 Comparison with Other Languages

| Python | JavaScript | C++ |
|--------|-----------|-----|
| `class A:` | `class A {` | `class A { public: ... };` |
| `__init__(self)` | `constructor()` | `A() {}` |
| `self.x` | `this.x` | `this->x` or `x` |
| `A(1)` | `new A(1)` | `A a(1);` |
| `b = a` (reference) | `b = a` (reference) | `A b = a;` — a **copy**! |

In C++, assigning an object creates a copy; a reference requires `A& b = a;`
or a pointer.
