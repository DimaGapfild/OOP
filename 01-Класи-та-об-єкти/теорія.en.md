# Chapter 1. Classes and Objects

## 1.1 Why OOP

In the procedural approach, **data and functions are kept apart**:

**Python**

```python
book = {"title": "Kobzar", "pages": 320}

def is_long(b):
    return b["pages"] > 300
```

**JavaScript**

```js
const book = { title: "Kobzar", pages: 320 };

function isLong(b) {
    return b.pages > 300;
}
```

**C++**

```cpp
struct BookData { std::string title; int pages; };

bool isLong(const BookData& b) {
    return b.pages > 300;
}
```

Nothing guarantees that the dictionary has a `pages` key, and the function
`is_long` is in no way tied to a "book". OOP **combines data and behavior**
into a single entity — an **object**.

Advantages of this approach:

- the code models the problem domain (student, account, shape);
- data is protected from arbitrary changes;
- code is easy to reuse and extend;
- large programs are split into small independent parts.

## 1.2 Class and Object

- A **class** is a description (template, type): what data an entity has and what it can do.
- An **object (instance)** is a concrete realization of a class with its own data.

Analogy: a class is a house blueprint, an object is a house that has been built.
Many houses can be built from one blueprint.

| Concept | What it is | Example |
|---------|-----------|---------|
| Class | a data type | `Book` |
| Object | an instance of a class | `Book("Kobzar", 320)` |
| Attribute (field) | the object's data | `title`, `pages` |
| Method | a function that belongs to a class | `is_long()` |

## 1.3 A Minimal Class

**Python**

```python
class Book:
    """A book with a title and a page count."""

    def __init__(self, title: str, pages: int):
        self.title = title
        self.pages = pages

    def is_long(self) -> bool:
        return self.pages > 300


b1 = Book("Kobzar", 320)
b2 = Book("Eneida", 180)
print(b1.title, b1.is_long())   # Kobzar True
print(b2.title, b2.is_long())   # Eneida False
```

**JavaScript**

```js
/** A book with a title and a page count. */
class Book {
    constructor(title, pages) {
        this.title = title;
        this.pages = pages;
    }

    isLong() {
        return this.pages > 300;
    }
}

const b1 = new Book("Kobzar", 320);
const b2 = new Book("Eneida", 180);
console.log(b1.title, b1.isLong());   // Kobzar true
console.log(b2.title, b2.isLong());   // Eneida false
```

**C++**

```cpp
#include <iostream>
#include <string>

// A book with a title and a page count.
class Book {
public:
    std::string title;
    int pages;

    Book(std::string title, int pages) : title(title), pages(pages) {}

    bool isLong() const {
        return pages > 300;
    }
};

int main() {
    Book b1("Kobzar", 320);
    Book b2("Eneida", 180);
    std::cout << b1.title << " " << b1.isLong() << "\n";   // Kobzar 1
    std::cout << b2.title << " " << b2.isLong() << "\n";   // Eneida 0
}
```

Every object has **its own set of attributes**: changing `b1.pages` does not
affect `b2`.

**Python**

```python
b1.pages = 100
print(b1.is_long(), b2.pages)   # False 180
```

**JavaScript**

```js
b1.pages = 100;
console.log(b1.isLong(), b2.pages);   // false 180
```

**C++**

```cpp
b1.pages = 100;
std::cout << b1.isLong() << " " << b2.pages << "\n";   // 0 180
```

> **Language difference: the wrong number of arguments.**
> What happens if only one parameter is passed to the constructor?
>
> ```python
> b = Book("Kobzar")       # TypeError: missing 1 required positional argument
> ```
>
> ```js
> const b = new Book("Kobzar");   // NO error: pages === undefined
> b.isLong();                     // false — because undefined > 300 is false
> ```
>
> ```cpp
> Book b("Kobzar");        // COMPILE error: no matching constructor
> ```
>
> | | Python | JavaScript | C++ |
> |---|---|---|---|
> | Too few arguments | `TypeError` at run time | silently `undefined` | compile error |
> | Too many arguments | `TypeError` at run time | silently ignored | compile error |
> | When the error shows up | when **this line** runs | possibly never (a wrong result) | **before** the program runs |
>
> Python does not compile the program in advance: if the line
> `Book("Kobzar")` sits in a function that is never called, there is no
> error. In JavaScript the error is the sneakiest: the object is created
> "broken" and the consequences show up somewhere else. That is why in JS
> parameters are worth checking explicitly in the constructor.

> **Language difference: new attributes and typos.** In Python and
> JavaScript an object can be given an attribute that the class does not
> have — and a typo silently creates a new attribute:
>
> ```python
> b1.pagse = 100           # a typo: a NEW attribute is created, pages is unchanged
> ```
>
> ```js
> b1.pagse = 100;          // the same — no error
> ```
>
> ```cpp
> b1.pagse = 100;          // compile error: no member named 'pagse'
> ```
>
> In C++ the set of fields is fixed by the class declaration.

## 1.4 Reference to the Current Object

`self` is a reference to the **current object**. It is the first parameter of every
method; when a method is called, Python supplies it automatically:

**Python**

```python
b1.is_long()            # the same as Book.is_long(b1)
```

In JavaScript the role of `self` is played by `this`, in C++ by `this`
(a pointer), but both languages pass it **implicitly** — it does not
appear in the parameter list:

**JavaScript**

```js
b1.isLong();            // inside the method this === b1
```

**C++**

```cpp
b1.isLong();            // inside the method this == &b1
```

> **Language difference: a "lost" `this`.** In Python a method taken
> from an object remembers its object (`f = b1.is_long; f()` works).
> In JavaScript it does not: `this` is determined **at the moment of the call**:
>
> ```js
> const f = b1.isLong;
> f();                     // TypeError: Cannot read properties of undefined
> setTimeout(b1.isLong, 0);       // the same problem with callbacks
> setTimeout(() => b1.isLong(), 0);   // correct: an arrow function
> ```
>
> In C++ a method cannot be "detached" from an object like this: a
> pointer to a member (`&Book::isLong`) is called only together with an
> object — `(b1.*f)()`.
>
> One more difference: in Python `self` is **mandatory** inside a method
> (`self.pages`), in JS it is `this.pages` (without `this` it refers to
> a non-existent variable, `ReferenceError`), and in C++ `this->` may be
> omitted: `pages` inside a method is the field.

## 1.5 Objects Are References

A variable stores a **reference** to an object, not the object itself.

**Python**

```python
a = Book("Kobzar", 320)
b = a                    # b points to the SAME object
b.pages = 1
print(a.pages)           # 1
print(a is b)            # True — the same object
c = Book("Kobzar", 1)
print(a is c)            # False — different objects (even though the data is equal)
```

**JavaScript**

```js
const a = new Book("Kobzar", 320);
const b = a;                     // b points to the SAME object
b.pages = 1;
console.log(a.pages);            // 1
console.log(a === b);            // true — the same object
const c = new Book("Kobzar", 1);
console.log(a === c);            // false — different objects
```

**C++** — here objects are **values** by default; references must be
declared explicitly:

```cpp
Book a("Kobzar", 320);
Book& b = a;                     // b is a reference to the SAME object
b.pages = 1;
std::cout << a.pages << "\n";    // 1
std::cout << (&a == &b) << "\n"; // 1 — the same address
Book c = a;                      // c is a COPY, a separate object
std::cout << (&a == &c) << "\n"; // 0
```

To get an independent copy, create a new object
(or use `copy.copy`, `copy.deepcopy`).

> **Language difference: what `==` compares.**
>
> | | Python | JavaScript | C++ |
> |---|---|---|---|
> | `a == b` for objects | calls `__eq__`; by default — whether it is the same object | `==` and `===` always compare **references** | compile error until `operator==` is defined |
> | "The same object?" | `a is b` | `a === b` | `&a == &b` |
>
> So in JS `new Book("Kobzar", 1) == new Book("Kobzar", 1)` is `false`,
> and this cannot be changed: to compare by value, write your own
> `equals()` method.

## 1.6 Functions for Working with Objects

**Python**

```python
type(b1)                     # <class '__main__.Book'>
isinstance(b1, Book)         # True
hasattr(b1, "title")         # True
getattr(b1, "pages")         # 320
vars(b1)                     # {'title': 'Kobzar', 'pages': 320}
```

**JavaScript**

```js
typeof b1;                       // "object"
b1.constructor.name;             // "Book"
b1 instanceof Book;              // true
"title" in b1;                   // true
b1["pages"];                     // 320
Object.entries(b1);              // [["title", "Kobzar"], ["pages", 320]]
```

**C++** — most checks happen **at compile time**; at run time only
type information is available:

```cpp
#include <typeinfo>

typeid(b1).name();               // type name (compiler-specific)
Book* p = &b1;                   // the compiler checks the type
// hasattr / getattr / vars — no equivalents: fields are known statically
```

> **Language difference: accessing a non-existent attribute.**
>
> ```python
> b1.color                 # AttributeError: 'Book' object has no attribute 'color'
> ```
>
> ```js
> b1.color;                // undefined — no error
> ```
>
> ```cpp
> b1.color;                // compile error
> ```

## 1.7 Objects Inside Objects

An attribute can be another object — this is how more complex models are built:

**Python**

```python
class Library:
    def __init__(self):
        self.books: list[Book] = []

    def add(self, book: Book) -> None:
        self.books.append(book)

    def total_pages(self) -> int:
        return sum(b.pages for b in self.books)
```

**JavaScript**

```js
class Library {
    constructor() {
        this.books = [];
    }

    add(book) {
        this.books.push(book);
    }

    totalPages() {
        return this.books.reduce((sum, b) => sum + b.pages, 0);
    }
}
```

**C++**

```cpp
#include <vector>

class Library {
public:
    void add(const Book& book) {
        books.push_back(book);
    }

    int totalPages() const {
        int sum = 0;
        for (const Book& b : books) sum += b.pages;
        return sum;
    }

private:
    std::vector<Book> books;
};
```

## 1.8 Comparison with Other Languages

| Python | JavaScript | C++ |
|--------|-----------|-----|
| `class A:` | `class A {` | `class A { public: ... };` |
| `__init__(self)` | `constructor()` | `A() {}` |
| `self.x` | `this.x` | `this->x` or `x` |
| `A(1)` | `new A(1)` | `A a(1);` |
| `b = a` (reference) | `b = a` (reference) | `A b = a;` — a **copy**! |

In C++, assigning an object creates a copy; a reference requires `A& b = a;`
or a pointer.
