# Practice Tasks for Chapter 9

**Task type:** design an exception hierarchy, context managers,
and contract checks.

Requirements for **every** task:
1. custom exceptions inherit from a shared base;
2. data about the error is stored as exception attributes;
3. docstrings in classes and functions;
4. at least 3 tests (including a check that the exception was actually raised).

> **Testing tools.** Use the standard tool for your language:
> - **Python** — `pytest` (`def test_...(): assert ...`) or the built-in `unittest`;
> - **JavaScript / TypeScript** — the built-in `node:test` + `node:assert` (Node 18+), or `Jest` / `Vitest`;
> - **C++** — `GoogleTest` or `Catch2`; for quick checks, `assert` from `<cassert>`.
>
> Tip: cover a normal case, an edge case (empty, zero, limit), and invalid input.

---

### Task 9.1
A hierarchy `BankError` → `InsufficientFundsError(balance, needed)`,
`AccountClosedError`. An `Account` class: `deposit`, `withdraw`, `close`.
Show that `except BankError` catches them all.

### Task 9.2
`ValidationError(field, message)`. A function `validate_user(data)`
checks the name (non-empty), age (0..150), email (contains `@`) and raises
an error on the first problematic field; `collect_errors(data)` returns
a list of all of them.

### Task 9.3
`ConfigError`. A function `load_port(config)` turns `KeyError` and
`ValueError` into `ConfigError` via `raise ... from`; a port outside
1..65535 is also a `ConfigError`. Check `__cause__`.

### Task 9.4
`retry(fn, attempts, exceptions)` — calls `fn` until the first
success. After the attempts are exhausted it raises `RetryError` with a list of all errors.
Test it on an "unstable" function.

### Task 9.5
A `Database` (a `data` dictionary) and a context manager `Transaction(db)`:
if an exception occurs inside `with`, all changes are rolled back and the exception
is not swallowed.

### Task 9.6
A resource manager: a `Resource` class (`__enter__`/`__exit__`)
and a function `opened(name, log)` via `@contextmanager`. Check
the order in which nested resources are closed and closing on error.

### Task 9.7
Decorators `requires(pred, msg)` and `ensures(pred, msg)`, an exception
`ContractError`. Apply them to `isqrt(n)` (n ≥ 0; r² ≤ n < (r+1)²)
and to `Stack.pop()` (the stack is not empty).

### Task 9.8
An `Interval(lo, hi)` class with the invariant `lo <= hi`. The methods `shift(d)`,
`widen(k)`, `set_lo(x)` raise `InvariantError` and **do not change**
the object if the invariant would be violated.

### Task 9.9
A `Result` class with `ok(value)` / `err(error)`, methods `is_ok()`,
`map(fn)`, `unwrap()` (raises the error if `err`), `unwrap_or(default)`.
The functions `safe_div(a, b)` and `parse_int(s)` return a `Result`.

### Task 9.10
Layers: `Repository.get(id)` raises `NotFoundError`; `UserService`
turns it into `UserNotFoundError(user_id)` with a chain;
a function `process_all(items, fn)` processes all items and at the end
raises `BatchError(errors)` if there were errors.
