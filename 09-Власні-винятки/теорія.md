# Розділ 9. Власні винятки та контракти

## 9.1 Навіщо власні винятки

Вбудовані `ValueError`, `KeyError` тощо описують **технічну** помилку.
Власний виняток описує помилку **предметної області**:
`InsufficientFundsError`, `UserNotFoundError`. Перевага — код, що
ловить помилки, читається як опис бізнес-правил, а не техніки.

**Python**

```python
class BankError(Exception):
    """Базовий виняток банківського модуля."""

class InsufficientFundsError(BankError):
    def __init__(self, balance: float, needed: float):
        super().__init__(f"недостатньо коштів: є {balance}, потрібно {needed}")
        self.balance = balance          # дані про помилку — атрибути
        self.needed = needed
```

**JavaScript**

```js
/** Базовий виняток банківського модуля. */
class BankError extends Error {
    constructor(message, options) {
        super(message, options);
        this.name = this.constructor.name;
    }
}

class InsufficientFundsError extends BankError {
    constructor(balance, needed) {
        super(`недостатньо коштів: є ${balance}, потрібно ${needed}`);
        this.balance = balance;         // дані про помилку — поля
        this.needed = needed;
    }
}
```

**C++**

```cpp
#include <stdexcept>
#include <string>

// Базовий виняток банківського модуля.
class BankError : public std::runtime_error {
public:
    using std::runtime_error::runtime_error;
};

class InsufficientFundsError : public BankError {
public:
    InsufficientFundsError(double balance, double needed)
        : BankError("недостатньо коштів: є " + std::to_string(balance) +
                    ", потрібно " + std::to_string(needed)),
          balance(balance), needed(needed) {}

    const double balance;               // дані про помилку — поля
    const double needed;
};
```

Правила:

- успадковуйте від `Exception` (не від `BaseException`);
- назва закінчується на `Error` (для помилок);
- створіть **базовий** виняток модуля — користувач зможе ловити все одним `except BankError`;
- зберігайте корисні дані як атрибути, а не лише текст повідомлення.

## 9.2 Ієрархія винятків

```
Exception
└── BankError
    ├── InsufficientFundsError
    └── AccountClosedError
```

**Python**

```python
try:
    account.withdraw(500)
except InsufficientFundsError as e:      # конкретна помилка — спершу
    print(e.needed - e.balance)
except BankError:                        # решта банківських — потім
    ...
```

**JavaScript** — `catch` лише один, тип перевіряють через `instanceof`:

```js
try {
    account.withdraw(500);
} catch (e) {
    if (e instanceof InsufficientFundsError) {   // конкретна помилка — спершу
        console.log(e.needed - e.balance);
    } else if (e instanceof BankError) {         // решта банківських — потім
        // ...
    } else {
        throw e;                                 // чужі помилки — далі
    }
}
```

**C++** — ловлять **за константним посиланням**:

```cpp
try {
    account.withdraw(500);
} catch (const InsufficientFundsError& e) {      // конкретна помилка — спершу
    std::cout << e.needed - e.balance << "\n";
} catch (const BankError& e) {                   // решта банківських — потім
    // ...
}
```

Порядок `except` має значення: **спочатку конкретні, потім загальні**.

> **Різниця між мовами: що можна кинути й як ловити.**
>
> - **Python** — лише об'єкти-нащадки `BaseException` (`raise "текст"` —
>   `TypeError`).
> - **JavaScript** — **будь-що**: `throw "помилка"` чи `throw 42` дозволені,
>   але тоді немає ні стеку викликів, ні `instanceof`. Завжди кидайте
>   `Error` або його нащадків.
> - **C++** — теж будь-що (`throw 42;`), але прийнято кидати нащадків
>   `std::exception`. Ловити треба **за посиланням**: `catch (BankError e)`
>   (за значенням) **зрізає** `InsufficientFundsError` до `BankError` —
>   перевизначені віртуальні методи й додаткові поля губляться.
>
> Неперехоплений виняток: Python і Node.js друкують трасування й
> завершують програму; C++ викликає `std::terminate` (аварійне завершення,
> деструктори можуть не виконатися).

## 9.3 Перехоплення та обробка винятків

**Python**

```python
try:
    value = int(text)               # небезпечна операція (мінімум коду!)
except ValueError:
    value = 0                       # обробка
else:
    log("розібрано")                # лише якщо виняток НЕ виник
finally:
    cleanup()                       # ЗАВЖДИ: і при помилці, і при return
```

**JavaScript** — блоку `else` немає, код ставлять у кінець `try`:

```js
let value;
try {
    value = Number.parseInt(text, 10);
    if (Number.isNaN(value)) throw new RangeError("не число");
    log("розібрано");
} catch {
    value = 0;                      // обробка
} finally {
    cleanup();                      // ЗАВЖДИ
}
```

**C++** — `finally` немає: прибирання роблять **деструктори** (RAII):

```cpp
int value;
{
    Cleanup guard;                  // деструктор викличеться ЗАВЖДИ
    try {
        value = std::stoi(text);
        log("розібрано");
    } catch (const std::invalid_argument&) {
        value = 0;                  // обробка
    }
}                                   // тут guard.~Cleanup() → cleanup()
```

## 9.4 Ланцюжки винятків

Перетворюючи технічну помилку на предметну, **не губіть причину**:

**Python**

```python
try:
    port = int(config["port"])
except KeyError as e:
    raise ConfigError("не вказано port") from e      # e -> __cause__
```

**JavaScript**

```js
const port = config.port;
if (port === undefined) {
    throw new ConfigError("не вказано port", { cause: new Error("no key") });
}
// причина доступна як err.cause
```

**C++**

```cpp
try {
    int port = std::stoi(config.at("port"));
} catch (const std::out_of_range&) {
    std::throw_with_nested(ConfigError("не вказано port"));
}
// причину дістають через std::rethrow_if_nested(e)
```

`raise ... from e` зберігає початкову помилку у `__cause__`;
`raise ... from None` приховує її навмисно. Без `from` у `__context__`
потрапляє виняток, що оброблявся в цей момент.

## 9.5 Гарантоване звільнення ресурсів

Гарантують звільнення ресурсу — аналог RAII у C++.

**Python**

```python
class Transaction:
    def __init__(self, db): self.db = db
    def __enter__(self):
        self.snapshot = dict(self.db.data)
        return self
    def __exit__(self, exc_type, exc, tb):
        if exc_type is not None:
            self.db.data = self.snapshot     # відкат
        return False                         # False/None — виняток іде далі
```

**JavaScript** — `try/finally` (або `using` з `[Symbol.dispose]` у нових рушіях):

```js
function inTransaction(db, action) {
    const snapshot = { ...db.data };
    try {
        return action();
    } catch (e) {
        db.data = snapshot;            // відкат
        throw e;                       // виняток іде далі
    }
}
```

**C++** — RAII: деструктор відкочує зміни, якщо не було `commit()`:

```cpp
class Transaction {
public:
    explicit Transaction(Db& db) : db(db), snapshot(db.data) {}

    ~Transaction() {
        if (!committed) db.data = snapshot;   // відкат
    }

    void commit() { committed = true; }

private:
    Db& db;
    std::map<std::string, int> snapshot;
    bool committed = false;
};
```

Коротка форма:

**Python**

```python
from contextlib import contextmanager

@contextmanager
def opened(name, log):
    log.append(f"open {name}")
    try:
        yield name
    finally:
        log.append(f"close {name}")
```

**JavaScript** — функція, що приймає «тіло» як колбек:

```js
function opened(name, log, body) {
    log.push(`open ${name}`);
    try {
        return body(name);
    } finally {
        log.push(`close ${name}`);
    }
}
```

**C++**

```cpp
class Opened {
public:
    Opened(std::string name, std::vector<std::string>& log)
        : name(name), log(log) { log.push_back("open " + name); }
    ~Opened() { log.push_back("close " + name); }

private:
    std::string name;
    std::vector<std::string>& log;
};
```

## 9.6 Контракти: проєктування за контрактом

**Контракт** методу складається з:

| Елемент | Питання | Хто відповідає |
|---------|---------|----------------|
| **Передумова** (precondition) | що має бути істинним **до** виклику | викликач |
| **Післяумова** (postcondition) | що метод **гарантує** після виконання | метод |
| **Інваріант** | що істинне для об'єкта **завжди** між викликами | клас |

Порушення передумови — вина **викликача** (кидаємо `ValueError`/
`ContractError`). Порушення післяумови чи інваріанта — **помилка
в самому коді** (`assert`, `InvariantError`).

**Python**

```python
def requires(pred, msg):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*a, **kw):
            if not pred(*a, **kw):
                raise ContractError(msg)
            return fn(*a, **kw)
        return wrapper
    return deco
```

**JavaScript** — функція вищого порядку замість декоратора:

```js
function requires(pred, msg, fn) {
    return function (...args) {
        if (!pred(...args)) throw new ContractError(msg);
        return fn.apply(this, args);
    };
}
```

**C++** — передумову перевіряють на початку методу; `assert` (з
`<cassert>`) вимикається макросом `NDEBUG`, як і `python -O`:

```cpp
#include <cassert>

void withdraw(double amount) {
    if (amount <= 0) {                         // передумова
        throw std::invalid_argument("amount має бути > 0");
    }
    balance -= amount;
    assert(balance >= 0);                      // інваріант (внутрішнє припущення)
}
```

`assert` вимикається прапорцем `python -O`, тому **не використовуйте
його для перевірки вхідних даних користувача** — лише для внутрішніх
припущень.

## 9.7 Виняток чи значення-результат?

| Підхід | Коли |
|--------|------|
| Виняток | помилка **виняткова**, рівень виклику не може її обробити |
| `None` / код повернення | відсутність результату — звичайна ситуація |
| `Result` (ok / err) | помилка — **очікуваний** результат; хочемо змусити її обробити |

**Python**

```python
r = safe_div(10, 0)                  # Result, а не виняток
value = r.unwrap_or(0)
```

**JavaScript**

```js
const r = safeDiv(10, 0);            // { ok: false, error: "..." }
const value = r.ok ? r.value : 0;
```

**C++** — `std::optional` або C++23 `std::expected`:

```cpp
#include <expected>

std::expected<double, std::string> safeDiv(double a, double b) {
    if (b == 0) return std::unexpected("ділення на нуль");
    return a / b;
}

double value = safeDiv(10, 0).value_or(0);
```

## 9.8 Агрегування помилок

Іноді потрібно обробити всі елементи й повідомити про всі помилки разом
(`ExceptionGroup` у Python 3.11+, або власний `BatchError`).

## 9.9 Порівняння з іншими мовами

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Базовий клас | `Exception` | `Error` | `std::exception` |
| Ланцюжок | `raise X from e` | `new Error(msg, { cause: e })` | `std::throw_with_nested` |
| `finally` | є | є | **немає** — RAII (деструктори) |
| Контекстний менеджер | `with` | `try/finally`, `using` (нове) | RAII |
| Специфікація винятків | немає | немає | `noexcept` |
