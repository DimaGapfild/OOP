# Розділ 3. Інкапсуляція та властивості

## 3.1 Що таке інкапсуляція

**Інкапсуляція** — приховування внутрішнього стану об'єкта та доступ
до нього лише через чітко визначений інтерфейс (методи).

Навіщо:

- **захист інваріантів** — баланс не може стати від'ємним, вік — 500;
- **свобода змін** — внутрішнє подання можна змінити, не ламаючи користувачів класу;
- **менше помилок** — дані змінюються в одному місці, а не по всій програмі.

**Python**

```python
class BadAccount:
    def __init__(self):
        self.balance = 0

acc = BadAccount()
acc.balance = -1_000_000      # ніхто не завадить
```

**JavaScript**

```js
class BadAccount {
    constructor() {
        this.balance = 0;
    }
}

const acc = new BadAccount();
acc.balance = -1_000_000;     // ніхто не завадить
```

**C++**

```cpp
struct BadAccount {
    double balance = 0;       // у struct усе публічне за замовчуванням
};

BadAccount acc;
acc.balance = -1'000'000;     // ніхто не завадить
```

## 3.2 Рівні доступу

Python не забороняє доступ технічно — діють **угоди**:

| Запис | Назва | Зміст |
|-------|-------|-------|
| `self.name` | публічний | частина інтерфейсу |
| `self._cache` | «захищений» | деталь реалізації, не чіпати ззовні |
| `self.__secret` | «приватний» | name mangling → `_Class__secret` |

**Python**

```python
class A:
    def __init__(self):
        self.__x = 1

a = A()
# a.__x               # AttributeError
print(a._A__x)        # 1 — технічно доступно, але так робити не слід
```

У JavaScript і C++ приватність **справжня** — її перевіряє мова:

**JavaScript**

```js
class A {
    #x = 1;                   // приватне поле
}

const a = new A();
// a.#x                       // SyntaxError — доступу ззовні немає
```

**C++**

```cpp
class A {
private:
    int x = 1;
protected:
    int y = 2;                // доступне нащадкам
public:
    int z = 3;
};

A a;
// a.x                        // помилка компіляції
```

Name mangling захищає від **випадкових** конфліктів імен у нащадках, а не
від зловмисника.

> **Різниця між мовами: звернення до приватного поля ззовні.**
>
> ```python
> a.__x                    # AttributeError (але a._A__x працює)
> ```
>
> ```js
> a.#x;                    // SyntaxError — код навіть не запуститься
> a.x;                     // undefined — БЕЗ помилки: це просто інше, публічне поле
> ```
>
> ```cpp
> a.x;                     // помилка компіляції: 'x' is a private member
> ```
>
> У JS `#x` і `x` — **два різні поля**; випадково написати `this.x`
> замість `this.#x` — тиха помилка.

## 3.3 Геттери й сеттери

`@property` дозволяє читати/писати «як атрибут», але з перевіркою:

**Python**

```python
class Person:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age               # викличе сеттер!

    @property
    def age(self) -> int:
        return self._age

    @age.setter
    def age(self, value: int) -> None:
        if not 0 <= value <= 150:
            raise ValueError("вік поза межами 0..150")
        self._age = value


p = Person("Іван", 20)
p.age = 21         # сеттер
p.age = 500        # ValueError
```

**JavaScript**

```js
class Person {
    #age;

    constructor(name, age) {
        this.name = name;
        this.age = age;              // викличе сеттер!
    }

    get age() {
        return this.#age;
    }

    set age(value) {
        if (value < 0 || value > 150) {
            throw new RangeError("вік поза межами 0..150");
        }
        this.#age = value;
    }
}

const p = new Person("Іван", 20);
p.age = 21;        // сеттер
p.age = 500;       // RangeError
```

**C++** — властивостей немає, використовують пару методів:

```cpp
#include <stdexcept>

class Person {
public:
    Person(std::string name, int age) : name(name) {
        setAge(age);                 // перевірка і в конструкторі
    }

    int age() const { return age_; }

    void setAge(int value) {
        if (value < 0 || value > 150) {
            throw std::out_of_range("вік поза межами 0..150");
        }
        age_ = value;
    }

    std::string name;

private:
    int age_;
};

Person p("Іван", 20);
p.setAge(21);      // сеттер
p.setAge(500);     // std::out_of_range
```

Три форми властивості:

| Що | Як |
|----|----|
| лише читання | `@property` без сеттера (спроба запису → `AttributeError`) |
| читання й запис з перевіркою | `@property` + `@x.setter` |
| видалення | `@x.deleter` |

> **Різниця між мовами: описка в імені властивості.** Валідація в
> сеттері не допоможе, якщо в імені помилились:
>
> ```python
> p.agee = 500             # створено новий атрибут agee — перевірку обійдено
> ```
>
> ```js
> p.agee = 500;            // так само, без помилки
> ```
>
> ```cpp
> p.setAgee(500);          // помилка компіляції
> ```
>
> У Python від цього захищає `__slots__` (заборона нових атрибутів), у JS —
> `Object.seal(this)` наприкінці конструктора.

## 3.4 Обчислювані властивості

Значення не зберігається, а обчислюється з інших даних:

**Python**

```python
class Rectangle:
    def __init__(self, w, h):
        self.w, self.h = w, h

    @property
    def area(self):              # завжди актуальна
        return self.w * self.h
```

**JavaScript**

```js
class Rectangle {
    constructor(w, h) {
        [this.w, this.h] = [w, h];
    }

    get area() {                 // завжди актуальна
        return this.w * this.h;
    }
}
```

**C++**

```cpp
class Rectangle {
public:
    Rectangle(double w, double h) : w(w), h(h) {}

    double area() const {        // завжди актуальна
        return w * h;
    }

    double w, h;
};
```

## 3.5 Кешування обчислень

**Python**

```python
class Circle:
    def __init__(self, r):
        self._r = r
        self._area = None

    @property
    def r(self): return self._r

    @r.setter
    def r(self, v):
        self._r = v
        self._area = None        # скидаємо кеш

    @property
    def area(self):
        if self._area is None:
            self._area = 3.141592653589793 * self._r ** 2
        return self._area
```

**JavaScript**

```js
class Circle {
    #r;
    #area = null;

    constructor(r) {
        this.#r = r;
    }

    get r() { return this.#r; }

    set r(v) {
        this.#r = v;
        this.#area = null;       // скидаємо кеш
    }

    get area() {
        if (this.#area === null) {
            this.#area = Math.PI * this.#r ** 2;
        }
        return this.#area;
    }
}
```

**C++** — `mutable` дозволяє змінювати кеш навіть у `const`-методі:

```cpp
#include <cmath>
#include <optional>

class Circle {
public:
    explicit Circle(double r) : r_(r) {}

    double r() const { return r_; }

    void setR(double v) {
        r_ = v;
        area_.reset();           // скидаємо кеш
    }

    double area() const {
        if (!area_) {
            area_ = M_PI * r_ * r_;
        }
        return *area_;
    }

private:
    double r_;
    mutable std::optional<double> area_;
};
```

(У стандартній бібліотеці є `functools.cached_property`.)

## 3.6 Не віддавайте внутрішній стан

**Python**

```python
class Inventory:
    def __init__(self):
        self._items = {}

    def items(self):
        return dict(self._items)     # КОПІЯ, а не сам словник
```

**JavaScript**

```js
class Inventory {
    #items = new Map();

    items() {
        return new Map(this.#items);  // КОПІЯ, а не сама Map
    }
}
```

**C++** — повертаємо копію **або** константне посилання (змінити через
нього не можна):

```cpp
#include <map>

class Inventory {
public:
    std::map<std::string, int> items() const {
        return items_;                // КОПІЯ
    }

    const std::map<std::string, int>& view() const {
        return items_;                // лише для читання, без копіювання
    }

private:
    std::map<std::string, int> items_;
};
```

Якщо повернути `self._items`, зовнішній код зможе змінити стан в обхід методів.

## 3.7 Порівняння з іншими мовами

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Приватність | угода `_x`, `__x` | `#x` — справжня | `private:` — справжня |
| Геттер | `@property` | `get x()` | метод `x() const` |
| Сеттер | `@x.setter` | `set x(v)` | метод `setX(v)` |
| Лише читання | немає сеттера | немає `set` | `const`-метод, без сеттера |
