# Chapter 3. Encapsulation and Properties

## 3.1 What Is Encapsulation

**Encapsulation** means hiding an object's internal state and giving access
to it only through a well-defined interface (methods).

Why:

- **protecting invariants** — a balance cannot become negative, an age cannot be 500;
- **freedom to change** — the internal representation can change without breaking the class's users;
- **fewer bugs** — data is modified in one place rather than throughout the program.

**Python**

```python
class BadAccount:
    def __init__(self):
        self.balance = 0

acc = BadAccount()
acc.balance = -1_000_000      # nothing prevents this
```

**JavaScript**

```js
class BadAccount {
    constructor() {
        this.balance = 0;
    }
}

const acc = new BadAccount();
acc.balance = -1_000_000;     // nothing prevents this
```

**C++**

```cpp
struct BadAccount {
    double balance = 0;       // everything in a struct is public by default
};

BadAccount acc;
acc.balance = -1'000'000;     // nothing prevents this
```

## 3.2 Access Levels

Python does not technically forbid access — **conventions** apply:

| Notation | Name | Meaning |
|----------|------|---------|
| `self.name` | public | part of the interface |
| `self._cache` | "protected" | an implementation detail, do not touch from outside |
| `self.__secret` | "private" | name mangling → `_Class__secret` |

**Python**

```python
class A:
    def __init__(self):
        self.__x = 1

a = A()
# a.__x               # AttributeError
print(a._A__x)        # 1 — technically accessible, but you should not do this
```

In JavaScript and C++ privacy is **real** — the language enforces it:

**JavaScript**

```js
class A {
    #x = 1;                   // a private field
}

const a = new A();
// a.#x                       // SyntaxError — no access from outside
```

**C++**

```cpp
class A {
private:
    int x = 1;
protected:
    int y = 2;                // accessible to subclasses
public:
    int z = 3;
};

A a;
// a.x                        // compile error
```

Name mangling protects against **accidental** name clashes in subclasses, not
against a malicious user.

> **Language difference: accessing a private field from outside.**
>
> ```python
> a.__x                    # AttributeError (but a._A__x works)
> ```
>
> ```js
> a.#x;                    // SyntaxError — the code will not even start
> a.x;                     // undefined — NO error: it is just another, public field
> ```
>
> ```cpp
> a.x;                     // compile error: 'x' is a private member
> ```
>
> In JS `#x` and `x` are **two different fields**; accidentally writing
> `this.x` instead of `this.#x` is a silent bug.

## 3.3 Getters and Setters

`@property` lets you read and write "like an attribute", but with validation:

**Python**

```python
class Person:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age               # this calls the setter!

    @property
    def age(self) -> int:
        return self._age

    @age.setter
    def age(self, value: int) -> None:
        if not 0 <= value <= 150:
            raise ValueError("age out of range 0..150")
        self._age = value


p = Person("Ivan", 20)
p.age = 21         # setter
p.age = 500        # ValueError
```

**JavaScript**

```js
class Person {
    #age;

    constructor(name, age) {
        this.name = name;
        this.age = age;              // this calls the setter!
    }

    get age() {
        return this.#age;
    }

    set age(value) {
        if (value < 0 || value > 150) {
            throw new RangeError("age out of range 0..150");
        }
        this.#age = value;
    }
}

const p = new Person("Ivan", 20);
p.age = 21;        // setter
p.age = 500;       // RangeError
```

**C++** — there are no properties, a pair of methods is used instead:

```cpp
#include <stdexcept>

class Person {
public:
    Person(std::string name, int age) : name(name) {
        setAge(age);                 // validate in the constructor too
    }

    int age() const { return age_; }

    void setAge(int value) {
        if (value < 0 || value > 150) {
            throw std::out_of_range("age out of range 0..150");
        }
        age_ = value;
    }

    std::string name;

private:
    int age_;
};

Person p("Ivan", 20);
p.setAge(21);      // setter
p.setAge(500);     // std::out_of_range
```

Three forms of a property:

| What | How |
|------|-----|
| read-only | `@property` without a setter (an attempt to write → `AttributeError`) |
| read and write with validation | `@property` + `@x.setter` |
| deletion | `@x.deleter` |

> **Language difference: a typo in a property name.** Validation in the
> setter does not help if the name is misspelled:
>
> ```python
> p.agee = 500             # a new attribute agee is created — the check is bypassed
> ```
>
> ```js
> p.agee = 500;            // the same, no error
> ```
>
> ```cpp
> p.setAgee(500);          // compile error
> ```
>
> In Python `__slots__` protects against this (no new attributes allowed),
> in JS — `Object.seal(this)` at the end of the constructor.

## 3.4 Computed Properties

The value is not stored but computed from other data:

**Python**

```python
class Rectangle:
    def __init__(self, w, h):
        self.w, self.h = w, h

    @property
    def area(self):              # always up to date
        return self.w * self.h
```

**JavaScript**

```js
class Rectangle {
    constructor(w, h) {
        [this.w, this.h] = [w, h];
    }

    get area() {                 // always up to date
        return this.w * this.h;
    }
}
```

**C++**

```cpp
class Rectangle {
public:
    Rectangle(double w, double h) : w(w), h(h) {}

    double area() const {        // always up to date
        return w * h;
    }

    double w, h;
};
```

## 3.5 Caching Computations

**Python**

```python
class Circle:
    def __init__(self, r):
        self._r = r
        self._area = None

    @property
    def r(self): return self._r

    @r.setter
    def r(self, v):
        self._r = v
        self._area = None        # invalidate the cache

    @property
    def area(self):
        if self._area is None:
            self._area = 3.141592653589793 * self._r ** 2
        return self._area
```

**JavaScript**

```js
class Circle {
    #r;
    #area = null;

    constructor(r) {
        this.#r = r;
    }

    get r() { return this.#r; }

    set r(v) {
        this.#r = v;
        this.#area = null;       // invalidate the cache
    }

    get area() {
        if (this.#area === null) {
            this.#area = Math.PI * this.#r ** 2;
        }
        return this.#area;
    }
}
```

**C++** — `mutable` allows the cache to change even inside a `const` method:

```cpp
#include <cmath>
#include <optional>

class Circle {
public:
    explicit Circle(double r) : r_(r) {}

    double r() const { return r_; }

    void setR(double v) {
        r_ = v;
        area_.reset();           // invalidate the cache
    }

    double area() const {
        if (!area_) {
            area_ = M_PI * r_ * r_;
        }
        return *area_;
    }

private:
    double r_;
    mutable std::optional<double> area_;
};
```

(The standard library has `functools.cached_property`.)

## 3.6 Do Not Hand Out Internal State

**Python**

```python
class Inventory:
    def __init__(self):
        self._items = {}

    def items(self):
        return dict(self._items)     # a COPY, not the dictionary itself
```

**JavaScript**

```js
class Inventory {
    #items = new Map();

    items() {
        return new Map(this.#items);  // a COPY, not the Map itself
    }
}
```

**C++** — return a copy **or** a const reference (it cannot be used to
modify the data):

```cpp
#include <map>

class Inventory {
public:
    std::map<std::string, int> items() const {
        return items_;                // a COPY
    }

    const std::map<std::string, int>& view() const {
        return items_;                // read-only, no copying
    }

private:
    std::map<std::string, int> items_;
};
```

If you return `self._items`, outside code can change the state while bypassing the methods.

## 3.7 Comparison with Other Languages

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Privacy | convention `_x`, `__x` | `#x` — real | `private:` — real |
| Getter | `@property` | `get x()` | a method `x() const` |
| Setter | `@x.setter` | `set x(v)` | a method `setX(v)` |
| Read-only | no setter | no `set` | a `const` method, no setter |
