# Final Project of the "Object-Oriented Programming" Course

## Goal

Design and implement a **console (or library) application** made of
several interacting classes that demonstrates: classes and encapsulation,
inheritance and polymorphism, abstraction, composition, custom exceptions,
collections, and the SOLID principles, as well as at least **two design
patterns**.

Language — Python 3 (JavaScript or C++ by agreement with the instructor).

## Topics to Choose From

### Option A. Task Tracker
Users, projects, tasks with a priority and a status (State),
tags, search and filtering, a change history (Command + undo), notifications
about overdue tasks (Observer), export to different formats (Strategy).

### Option B. Library / Rental
A catalog (books, magazines, discs — a hierarchy), readers, lending and
returns, late fines (Strategy), reservations
(Observer), search by various criteria, reports (Template Method).

### Option C. Banking System
Accounts of different types (inheritance + abstraction), transactions
(Command), fees (Decorator/Strategy), limits and checks
(custom exceptions, contracts), statements, notifications (Observer).

### Option D. Simulator (a game or an ecosystem)
Entities made of components (composition), behavior via
strategies, world events (Observer), a factory for creating creatures/items
(Factory), saving state (Memento — optional).

You may propose your own topic with approval.

## Requirements

### Mandatory (for a score of 3)

1. **At least 6 classes** with meaningful responsibilities.
2. **Classes and encapsulation:** hidden data, `@property` with validation,
   `__str__`/`__repr__`.
3. **Inheritance and polymorphism:** at least one hierarchy of 3+ classes;
   client code works through the base type.
4. **Abstraction:** at least one abstract class or interface.
5. **Custom exceptions:** a module base exception and at least two children.
6. **Tests:** at least 10 checks (`assert` or `unittest`/`pytest`).
7. **A UML class diagram** (Mermaid) in the project's `README.md`.
8. **README:** a description, how to run, a usage example, a list of the patterns and principles
   applied, and where exactly.

### Additional (for scores of 4–5)

9. **Patterns:** at least 2 for a 4, 3+ for a 5 — with
   a justification of why each is used.
10. **SOLID:** dependencies are passed in from outside (DI); demonstrate
    **extension without modifying** the existing code.
11. **Composition over inheritance** where the relationship is not "is a".
12. **Collections and iterators:** a custom collection (`__iter__`, `__len__`,
    `__getitem__`) or a generator.
13. **dataclass / Enum** for data and states.
14. **A sequence diagram** for the main scenario.
15. Tests on **fakes** (instead of real files/network).

## Stages of Work

| Stage | What we do | Result |
|-------|------------|--------|
| 1. Analysis | a list of entities, actions, rules | a list of requirements (user stories) |
| 2. Design | a class diagram, assigning responsibilities | UML in the README |
| 3. Skeleton | empty classes, interfaces, exceptions | code that imports |
| 4. Implementation | one class at a time + tests | green tests |
| 5. Integration | `main.py` with a full scenario | a demonstration |

| 7. Defense | a demonstration, answering questions | the grade |

## Common Mistakes

- a "god class" that does everything (a violation of S);
- inheriting just to reuse code (instead of composition);
- `isinstance` all over the code instead of polymorphism;
- depending on concrete classes: `self.db = MySqlDb()` inside a service;
- global state (Singleton) in every corner;
- `Exception("something went wrong")` exceptions without custom types;
- a diagram that does not match the code.

## Defense Questions

1. Which entities did you identify and why are the class boundaries where they are?
2. Where is polymorphism in the project and what would happen without it?
3. Which SOLID principle is easiest to violate in your project and how did you avoid it?
4. Show how to add a new capability (a new type/rule) **without edits** to the existing classes.
5. Why composition here rather than inheritance (or vice versa)?
6. How did you test a class that depends on an external system?
