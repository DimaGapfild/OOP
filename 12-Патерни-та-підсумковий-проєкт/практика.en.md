# Practice Tasks for Chapter 12

**Task type:** implement a design pattern for a given situation.

Requirements for **every** task:
1. client code depends on an abstraction, not on concrete classes;
2. docstrings in classes; the pattern's name in a comment/docstring;
3. show **extension without modifying the existing code**;
4. 3 checks using `assert`.

---

### Task 12.1 — Singleton
`AppConfig` — a single settings object: `set(key, value)`,
`get(key, default=None)`. Two instances created are one object.
Add `reset()` for tests.

### Task 12.2 — Factory
A `ShapeFactory` with a registry: `register(kind, creator)` and
`create(kind, *args)`. Built-in: `circle`, `rect`, `square`.
An unknown kind → `ValueError`. A new kind is added without changing the factory.

### Task 12.3 — Builder
A `PizzaBuilder`: `size()`, `sauce()`, `topping()`, `build()`.
`build()` checks the required parameters (size, sauce) and returns
an immutable `Pizza`. A `PizzaDirector` class with ready-made recipes.

### Task 12.4 — Adapter
Third-party classes: `LegacySensor.read_fahrenheit()` and
`OldLogger.write_line(level, text)`. Adapt them to the
interfaces `TemperatureSensor.celsius()` and `Logger.log(msg)`.

### Task 12.5 — Decorator
`Beverage` (`description()`, `cost()`), the base `Espresso`, `Tea`,
decorators `Milk`, `Sugar`, `Caramel`. Show arbitrary order
and repeated application (double sugar).

### Task 12.6 — Strategy
A `Sorter(strategy)` with strategies `BubbleSort`, `InsertionSort`,
`MergeSort`. The strategy can be changed at run time;
add a strategy that counts the number of comparisons.

### Task 12.7 — Observer
`Stock(symbol, price)` — the subject. Subscribers: `PriceLogger`
(records the history) and `AlertObserver(threshold)` (notifies when
the threshold is exceeded). Support `attach` / `detach`.

### Task 12.8 — Command
A `TextEditor` (text) and commands `InsertCommand(pos, text)`,
`DeleteCommand(pos, length)`. A `History`: `execute`, `undo`, `redo`.

### Task 12.9 — State
An order: `New → Paid → Shipped → Delivered`; it can be cancelled
only from `New` and `Paid`. Implement each state as a separate class;
an invalid transition → `InvalidTransition`.

### Task 12.10 — Mini-project "Shop"
Combine patterns: a `ProductFactory` (books/electronics with different
VAT), a `Cart` (Observer: listeners receive change events), discounts
(Strategy) with an optional gift-wrap decorator, a `History` of add/remove
commands with `undo`.
