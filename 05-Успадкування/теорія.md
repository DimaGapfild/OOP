# Розділ 5. Успадкування

## 5.1 Ідея

**Успадкування** — створення нового класу (**нащадка**, підкласу) на основі
існуючого (**предка**, базового класу): нащадок отримує всі атрибути й
методи предка і може додати власні або змінити успадковані.

Зв'язок «**є різновидом**» (is-a): собака *є* твариною, студент *є* особою.

**Python**

```python
class Animal:
    def __init__(self, name: str):
        self.name = name

    def speak(self) -> str:
        return "..."

    def intro(self) -> str:
        return f"{self.name} каже: {self.speak()}"


class Dog(Animal):                 # Dog успадковує Animal
    def speak(self) -> str:        # перевизначення (override)
        return "Гав!"


class Cat(Animal):
    def speak(self) -> str:
        return "Няв!"


print(Dog("Рекс").intro())         # Рекс каже: Гав!
```

**JavaScript**

```js
class Animal {
    constructor(name) {
        this.name = name;
    }

    speak() {
        return "...";
    }

    intro() {
        return `${this.name} каже: ${this.speak()}`;
    }
}

class Dog extends Animal {         // Dog успадковує Animal
    speak() {                      // перевизначення (override)
        return "Гав!";
    }
}

class Cat extends Animal {
    speak() {
        return "Няв!";
    }
}

console.log(new Dog("Рекс").intro());   // Рекс каже: Гав!
```

**C++** — метод, який можна перевизначати, позначають `virtual`:

```cpp
#include <iostream>
#include <string>

class Animal {
public:
    explicit Animal(std::string name) : name(name) {}
    virtual ~Animal() = default;

    virtual std::string speak() const {
        return "...";
    }

    std::string intro() const {
        return name + " каже: " + speak();
    }

protected:
    std::string name;
};

class Dog : public Animal {        // Dog успадковує Animal
public:
    using Animal::Animal;          // успадковуємо конструктор

    std::string speak() const override {
        return "Гав!";
    }
};

class Cat : public Animal {
public:
    using Animal::Animal;

    std::string speak() const override {
        return "Няв!";
    }
};

int main() {
    std::cout << Dog("Рекс").intro() << "\n";   // Рекс каже: Гав!
}
```

Термінологія:

| Термін | Значення |
|--------|----------|
| базовий клас, предок, суперклас | `Animal` |
| похідний клас, нащадок, підклас | `Dog` |
| перевизначення (override) | нащадок змінює метод предка |
| розширення | нащадок додає нові атрибути/методи |

> **Різниця між мовами: `virtual` у C++.** У Python і JavaScript
> **будь-який** метод можна перевизначити, і виклик завжди обирає версію
> за реальним типом об'єкта. У C++ це так лише для методів, позначених
> `virtual`:
>
> ```cpp
> Dog d("Рекс");
> Animal& a = d;
> a.speak();               // з virtual — "Гав!"; БЕЗ virtual — "..." (версія Animal)
> ```
>
> Друга пастка C++ — **зрізання** (slicing): присвоєння нащадка
> змінній-**значенню** базового типу копіює лише частину предка:
>
> ```cpp
> Animal copy = d;         // зрізання: від Dog лишився тільки Animal
> copy.speak();            // "..." — навіть із virtual
> ```
>
> Тому поліморфні об'єкти в C++ передають за посиланням (`Animal&`) або
> вказівником (`unique_ptr<Animal>`). У Python і JS змінні — завжди
> посилання, тож зрізання там не буває.

## 5.2 Звернення до предка

Якщо нащадок має власний `__init__`, він **повинен** викликати
конструктор предка, інакше атрибути предка не будуть створені.

**Python**

```python
class Employee:
    def __init__(self, name, salary):
        self.name, self.salary = name, salary

    def pay(self):
        return self.salary


class Manager(Employee):
    def __init__(self, name, salary, bonus):
        super().__init__(name, salary)     # ініціалізація частини-предка
        self.bonus = bonus

    def pay(self):
        return super().pay() + self.bonus  # розширення, а не заміна
```

**JavaScript** — `super(...)` у конструкторі обов'язковий і має йти
**до** першого звернення до `this`:

```js
class Employee {
    constructor(name, salary) {
        [this.name, this.salary] = [name, salary];
    }

    pay() {
        return this.salary;
    }
}

class Manager extends Employee {
    constructor(name, salary, bonus) {
        super(name, salary);               // ініціалізація частини-предка
        this.bonus = bonus;
    }

    pay() {
        return super.pay() + this.bonus;   // розширення, а не заміна
    }
}
```

**C++** — конструктор предка викликають у списку ініціалізації:

```cpp
class Employee {
public:
    Employee(std::string name, double salary) : name(name), salary(salary) {}
    virtual ~Employee() = default;

    virtual double pay() const {
        return salary;
    }

protected:
    std::string name;
    double salary;
};

class Manager : public Employee {
public:
    Manager(std::string name, double salary, double bonus)
        : Employee(name, salary), bonus(bonus) {}   // частина-предок

    double pay() const override {
        return Employee::pay() + bonus;             // розширення, а не заміна
    }

private:
    double bonus;
};
```

`super().метод()` — найкращий спосіб **повторно використати** логіку предка.

> **Різниця між мовами: забули викликати конструктор предка.**
>
> | Python | JavaScript | C++ |
> |---|---|---|
> | помилки немає; атрибутів предка просто не існує — `AttributeError` лише під час звернення до `self.name` | `ReferenceError` **одразу при створенні** об'єкта: «Must call super constructor» | компілятор сам викликає конструктор предка без параметрів; якщо такого немає — **помилка компіляції** |
>
> Python тут найменш суворий: об'єкт створюється «напівготовим», а
> помилка з'являється пізніше й в іншому місці.

## 5.3 Перевірка типу та ієрархії класів

**Python**

```python
d = Dog("Рекс")
isinstance(d, Dog)        # True
isinstance(d, Animal)     # True  — нащадок «є» предком
isinstance(d, Cat)        # False
issubclass(Dog, Animal)   # True
type(d) is Animal         # False — точний тип
```

**JavaScript**

```js
const d = new Dog("Рекс");
d instanceof Dog;                       // true
d instanceof Animal;                    // true  — нащадок «є» предком
d instanceof Cat;                       // false
Dog.prototype instanceof Animal;        // true  — аналог issubclass
d.constructor === Animal;               // false — точний тип
```

**C++**

```cpp
#include <type_traits>

Animal* a = new Dog("Рекс");
dynamic_cast<Dog*>(a) != nullptr;       // true
dynamic_cast<Cat*>(a) != nullptr;       // false
std::is_base_of_v<Animal, Dog>;         // true  — аналог issubclass (компіляція)
typeid(*a) == typeid(Animal);           // false — точний тип
delete a;
```

Перевіряйте `isinstance`, а не `type(x) == ...`: так працюють і підкласи.

## 5.4 Принцип підстановки Лісков (LSP)

Об'єкт-нащадок має **без проблем підставлятися** замість предка.
Нащадок не повинен посилювати вимоги до вхідних даних чи ламати
гарантії предка. Класичний зворотний приклад: `Square(Rectangle)`, у
якого зміна ширини змінює висоту — код, що працює з прямокутником,
ламається. Якщо зв'язок «є» штучний — використовуйте композицію
(розділ 8).

## 5.5 Множинне успадкування і MRO

Python дозволяє кілька предків:

**Python**

```python
class Flyer:
    def move(self): return "летить"

class Swimmer:
    def move(self): return "пливе"

class Duck(Flyer, Swimmer):
    pass

Duck().move()             # "летить" — береться з першого предка
print(Duck.__mro__)       # (Duck, Flyer, Swimmer, object)
```

**JavaScript** — множинного успадкування класів немає, тож міксини
реалізують функціями, що повертають клас:

```js
const Flyer = (Base) => class extends Base {
    move() { return "летить"; }
};
const Swimmer = (Base) => class extends Base {
    move() { return "пливе"; }
};

class Duck extends Flyer(Swimmer(Object)) {}

new Duck().move();       // "летить" — найближчий у ланцюжку прототипів
```

**C++** — множинне успадкування є, але неоднозначність треба розв'язати
**явно**, інакше помилка компіляції:

```cpp
struct Flyer   { std::string move() const { return "летить"; } };
struct Swimmer { std::string move() const { return "пливе"; } };

struct Duck : Flyer, Swimmer {
    using Flyer::move;   // явно обираємо версію
};

Duck().move();           // "летить"
```

Для «ромба» в C++ використовують `virtual`-успадкування
(`class B : virtual public A`), щоб частина `A` була одна.

**MRO** (Method Resolution Order) — порядок пошуку методу; обчислюється
алгоритмом C3. «Ромбоподібне» успадкування вирішується тим, що кожен
клас у MRO зустрічається один раз. `super()` йде **за MRO**, а не просто
«до батька».

## 5.6 Міксини

**Міксин** — невеликий клас із вузькою додатковою можливістю, який
«домішують» до інших (не створюють його екземплярів окремо):

**Python**

```python
class ReprMixin:
    def __repr__(self):
        fields = ", ".join(f"{k}={v!r}" for k, v in vars(self).items())
        return f"{type(self).__name__}({fields})"


class Point(ReprMixin):
    def __init__(self, x, y):
        self.x, self.y = x, y
```

**JavaScript** — міксин як функція над класом:

```js
const ReprMixin = (Base) => class extends Base {
    toString() {
        const fields = Object.entries(this)
            .map(([k, v]) => `${k}=${JSON.stringify(v)}`)
            .join(", ");
        return `${this.constructor.name}(${fields})`;
    }
};

class Point extends ReprMixin(Object) {
    constructor(x, y) {
        super();
        [this.x, this.y] = [x, y];
    }
}
```

**C++** — міксини роблять через шаблон **CRTP** (нащадок передає себе
як параметр шаблону):

```cpp
#include <sstream>

template <typename Derived>
struct PrintMixin {
    std::string toString() const {
        std::ostringstream out;
        static_cast<const Derived&>(*this).print(out);
        return out.str();
    }
};

struct Point : PrintMixin<Point> {
    int x, y;
    Point(int x, int y) : x(x), y(y) {}
    void print(std::ostream& out) const {
        out << "Point(x=" << x << ", y=" << y << ")";
    }
};
```

## 5.7 Успадкування чи композиція?

| Успадкування | Композиція |
|--------------|-----------|
| «є» (is-a) | «має» (has-a) |
| жорстка залежність від предка | гнучка заміна частин |
| зручне для невеликих природних ієрархій | краще за глибокі ієрархії |

Правило: **надавайте перевагу композиції**, успадкування — коли
зв'язок «є» справді природний.

## 5.8 Порівняння з іншими мовами

| | Python | JavaScript | C++ |
|---|--------|-----------|-----|
| Синтаксис | `class B(A):` | `class B extends A {` | `class B : public A {` |
| Виклик предка | `super().f()` | `super.f()` | `A::f()` |
| Конструктор предка | `super().__init__(..)` | `super(..)` (першим!) | список ініціалізації `: A(..)` |
| Множинне | є, MRO | немає (міксини-функції) | є, `virtual` для ромба |
| Перевірка типу | `isinstance` | `instanceof` | `dynamic_cast` |
